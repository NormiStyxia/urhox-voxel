# 敌人三视图与体素拆解方案

日期：2026-11-24。用途：把用户提供的五行概念板转成可交给美术、Lua 制作的结构规格。本次只形成方案，不修改敌人行为，不注册 Spawner，不运行、构建或提交。尺寸、预算与挂点均为制作建议，尚未完成模型或画面验收。

## 1. 概念板对应与制作基准

概念板从上到下对应：①木灵；②织巢虫群；③岩甲巨兽；④遗迹构装体；⑤时蚀灵体。前三行的名字是本方案对用户所列类别的对应；第三行的造型明确是直立石像，不将它改成现有四足石甲兽。若以后调整类别名称，沿用本行结构编号，避免拿错参考。

优先做④的悬浮石环与外露青色核心，再做⑤的钟背、兜帽、沙漏和收尖灵尾。两者不能都简化成“发光球加两只手”：④是离散的硬质构件，⑤是连续的灵体轮廓。

- 参照玩家高度 H = 1.70m，来自 `scripts/game/BlockCharacter.lua` 的现有比例注释；不是本次测得的角色包围盒。最终应以实际玩家站立模型复核。
- UrhoX：米制、Y 向上、+Z 正面、+X 角色自身右侧。正面画面左侧对应角色 +X；背面画面左右会反过来。
- 正面相机位于 +Z 看向原点；标准右侧面位于 +X；背面位于 -Z。三张同一比例、同一中立姿势、同一地面线，不能分别画成三个不同厚度的版本。板中现有侧图带透视，仅作为层次参考，不从图片像素推算精确尺寸。
- 全局根节点落在地面投影；下文坐标为该根节点局部米坐标，尺寸均为完整宽 X × 高 Y × 深 Z，不是半径。悬浮高度已经写进坐标，不能又额外加一次 hover。
- 主体体素边长暂取 s = 0.08m；大轮廓按 2–4 格成组，槽缝和眼睛可用 1 格，承重件/环壁至少 2 格。武器的 0.03m 不直接用于敌人大体积。

## 2. 现有系统的可用部分与边界

已读代码：`scripts/combat/WeaponBuilder.lua`、`WeaponGeometry.lua`、`enemies/EnemyVisual.lua`、`EnemyBase.lua`、`EnemyHitMaterial.lua`、`MossBeetle.lua`、`StoneSentry.lua`、`StoneBeast.lua`、`Spawner.lua`。已对照 Lua 开发指南、体素物理文档的网格/调色板章节，以及 Minecraft、VoxelTown、第三人称射击三个示例中的调色板、配置和节点/碰撞组织方式。

| 现有实现 | 本方案如何沿用 | 不能直接假定的能力 |
|---|---|---|
| WeaponGeometry 稀疏 cells + sparse + bounds，格中心用整数，边界有半格偏移 | 先编译敌人部件格子，再生成渲染体积；几何与受击数据分开 | WeaponBuilder.Compile 只认识武器目录，不能传敌人名称直接调用 |
| EnemyVisual.Sculpt 为椭球填充；body/back_armor/shell 自动拆八象限 | 复用其生命周期、部件组织和纯数值计数思路 | 当前 sculpt 配置不能准确表示环孔、方框、沙漏和阶梯刻纹；需要以后增加独立的纯 Lua 形状编译适配，不是改几个椭球半径就完成 |
| CreateVolume → GetGrid → SetSolid/SetVoxelMaterial → RebuildGeometry → SetParent | 所有新部件均可走这些项目已用 API；初始化时建网格，之后只动 Node | 不新增引擎 API，不引入骨骼蒙皮、约束物理、实时体素布料 |
| EnemyBase 为运动学角色：XZ 圆形脚印、解析受击球 | 碰撞建议用 radius/parts，视觉体积 collisionLayer/mask 都为 0 | config.height 参与攻击高度筛选，不会自动生成胶囊；不引入 Bullet 刚体或按外观自动推碰撞 |
| EnemyVisual.bones 是 Node；现有更新按名称写入旋转 | 新的挂点用 Node 层级、局部 position/rotation/scale | 当前通用 Update 不会自动播放悬浮环、钟针或复杂手臂动画；未来需独立视觉姿态适配 |
| EnemyHitMaterial 按实例/分组/domain/bank 克隆材质 | 保留调色板查表与局部受击反馈；多块同部位共用反馈组 | 当前 EnemyVoxelHit.shader 是不透明通道；不能靠调色板 alpha 直接获得透明灵体 |

视觉体积沿用现有敌人的“无物理定型”用途，不调用 FinalizeVolume / FinalizeVolumeAsDynamic；它们不参与地形破坏或动态碎块模拟。销毁逐个 world:RemoveVolume，再移除根节点。

新增格子编译器是后续制作工作，本次没有实现。不要为做预览复制第二个 VoxelPhysicsWorld，也不要修改只读 urhox-libs。

## 3. 遗迹构装体：第四行

### 3.1 三面锁定

**正面：**没有人脸，也没有腿。顶部是水平悬浮的厚石环，环前方中央嵌青色短槽；环下细青色轴连接胸框。胸部为四周石材包围的开放腔，青色菱形核心清晰外露，不能用一块整胸甲盖住。两侧各有分离的前臂石块，边缘金箍与青色折线符文；肩上另有一对小悬浮方石。下身只有短石座和下垂的青色尖端。

**右侧：**首先读出“前凸核心—中间框架—后方背板”三层；核心尖端在 +Z，背板在 -Z。石环有明确 Z 向深度和真实贯通孔，不是正面的一条弧线。手臂像有厚度的斜置石锤，前后金箍是包边结构，符文沿外侧面转折。身体、环、手臂之间保留空气缝，不能在侧面焊成整块。

**背面：**核心被方形背板遮住大部，中央只留短青色竖槽/锁孔形记号；背部不是复制正面的菱形窗口。左右手臂外侧符文延续，顶环前嵌槽不会无条件复制到后面。石座背面与胸框同轴，不能画成另一套腰部。

### 3.2 分件、尺寸与挂点

整机地面至最高点 2.40m（约 1.41H），最低可见尖端约 0.24m；实际可见轮廓高约 2.16m（1.27H）。手臂中立姿势总宽约 2.08m（1.22H），厚度约 0.80m（0.47H）。这是建议比例，不代表概念板已有实测数据。

| 类别 / 部件 | 根局部中心或挂点 XYZ | 完整包络尺寸 XYZ | 制作和运动约束 |
|---|---|---|---|
| 身体：胸框左右侧柱 | (±0.40, 1.44, 0) | 各 (0.24, 0.72, 0.40) | 中央留窗，两个侧柱及上下横梁在一个躯干 volume 编译，避免每根柱子一 draw |
| 身体：上/下框梁 | (0, 1.84/1.04, 0) | 各 (0.64, 0.16, 0.40) | 上梁不挡核心正面，框宽可微调但三面同步 |

| 功能件：顶石环 | (0, 2.24, 0) | (1.12, 0.24, 0.72) | XZ 平面环，壁厚0.16m，中间真空；正前槽位于 +Z 边 |
| 身体：下石座与尖端 | 石座 (0, 0.56, 0)，尖端 (0, 0.32, 0) | (0.56, 0.24, 0.40) / (0.16, 0.16, 0.16) | 不长出脚，石座和发光尖端可同一个下身 volume |
| 功能件：分离前臂 | 挂点 (±0.80, 1.44, 0)；体积中心约 (±0.80, 1.12, 0) | 各 (0.48, 0.72, 0.48) | 每侧一节点一 volume，金箍和符文写入同网格；中立可轻倾，表中包络不含倾斜外扩 |
| 功能件：肩上浮石 | (±0.88, 1.92, 0) | 各 (0.24, 0.24, 0.24) | 青色短尾与方石合并，每侧一 volume，不做可击落弹药的承诺 |

建议层级：root → body_pose → torso、core、crown_pivot、lower_body、arm_r_pivot、arm_l_pivot、satellite_r、satellite_l。背板可在 torso 同网格；若后续明确可开启，再独立成一件。手臂网格坐标必须减去挂点坐标，不能让它绕网格最小角摆动。

动画预留：body_pose 上下 ±0.04m；crown_pivot 小幅 Y 向转动；左右臂绕肩部 X 轴前后摆而不是整只横穿胸口；core 可低幅旋转，侧窗始终可见。浮石不做无限半径绕行。所有幅度是美术候选值，不是本轮新增行为。

### 3.3 碰撞与预算

建议地形脚印 radius = 0.62m；总高度筛选参考 2.40m。先用身体中心 (0, 1.44, 0)、radius = 0.58m 的单个解析受击球，命中名称 body，保持普通受击语义；发光核心只是视觉重点，是否弱点另行定稿。手臂、顶环与浮石先为非阻挡装饰，不将整块空气外包络做成墙。

若后续确实需要手臂独立受击，新增独立 parts 与球，并保证球跟随手臂节点变换；当前 SyncShapes 不读取骨骼动画，只同步根旋转、悬浮、部分姿态，不可假定受击球自动跟随挥臂。不得通过 hidden=true 偷用已有“背甲破碎后露核”分支：它依赖 parts.back_armor。

目标 1,800–2,600 个实心格，硬上限沿用现有单敌人 3,000 格；建议 9–12 个可见 volume，先合并同一刚性件里的边箍/符文，避免 body 命名触发现有八象限自动分件。最终数量须由新编译结果统计，不能把目标值当已测性能。

## 4. 时蚀灵体：第五行

### 4.1 三面锁定

**正面：**暗色圆角方脸藏在薄荷青兜帽里，两枚纵向暖黄眼睛；没有嘴和机械面罩。腹前悬挂沙漏，上下为金色座，中间细腰和暖色沙流可见。背后是镂空大齿环，中心不能填满；单根长指针从额头枢轴斜伸，不把它增加成两套钟面。下摆为分段收尖的灵尾，无腿。两侧是短袖状灵臂，外围飘带只保留少量断开的弧段。

**右侧：**脸是内层、兜帽是外层，沙漏在 +Z 腹前，厚齿环在 -Z 背后；顺序必须清楚。背环竖立在 XY 平面，与构装体的水平顶环方向不同。兜帽不能无限加厚成头盔，灵尾先向后收再下垂，沙漏有真实深度，不能是贴在脸下的图片。

**背面：**看到兜帽连续背壳、背侧小齿轮与大环厚边，不看到一张复制的脸；腹前沙漏在后视被灵体遮住大部。大环、小轮、枢轴从正面绕到背面的连接方向保持一致，不镜像重画符号。概念板前后指针角度的差异视为视图歧义：制作统一按同一根实体指针投影，验收时不能为迎合两张图而做双针。

### 4.2 分件、尺寸与挂点

地面至齿环顶建议 2.56m（1.51H）；灵尾最低约 0.24m，主体帽顶约 2.16m（1.27H）。连齿外径 1.76m（1.04H），身体宽约1.12m；飘带中立总宽控制在2.08m内。背环厚0.16m，最厚侧包络约0.96m。

| 类别 / 部件 | 根局部中心或挂点 XYZ | 完整包络尺寸 XYZ | 制作和运动约束 |
|---|---|---|---|
| 身体：兜帽 | (0, 1.76, 0) | (1.12, 0.80, 0.72) | 开口向 +Z；外壳2格厚，眉缘阶梯化，正面中央挖空以露出脸 |
| 身体：脸内胆 | (0, 1.76, 0.16) | (0.64, 0.48, 0.16) | 用深色填实体；眼睛各至少1×2格，留足眼间距 |
| 身体：躯干与灵尾 | 躯干 (0, 1.12, 0)，尾基 (0, 0.64, -0.08) | (0.80, 0.64, 0.56)，尾部逐层收尖至 y≈0.24 | 3–4组阶梯截面，偏移不超1格/层；不做连续薄透明裙片或四肢 |

| 功能件：单指针 | 枢轴 (0, 2.00, 0.40) | 轴到针尖长约0.72m、杆宽0.08–0.16m | 朝正面画面右上，即自身 -X/+Y；针尖空心菱形，针轴沿Z转动 |

建议层级：root → body_pose → hood、face、tail_pivot、hourglass_socket、clock_back_pivot、hand_pivot、sleeve_r、sleeve_l、ribbon_front、ribbon_back。小轮可与背环同刚性网格，若独立转动再拆出。

动画预留：主体缓慢上下 ±0.04m；灵尾绕 X 轴小幅摆动，顶部不离开躯干；指针沿 Z 轴分步转动；沙漏微摆不超过帽口投影边缘；飘带只整体旋转/轻摆，不按格子逐帧重建。所有静态图先固定同一时间姿态，再做动效，不能三面使用不同针角/轮位。

### 4.3 材质落地与碰撞

首版采用**不透明的浅青实体分层 + 真实空洞 + 青色发光边缘**表达灵体。它能保留当前敌人的不透明调色板和受击反馈；概念板的玻璃式通透仅为视觉目标，首版不承诺等同还原。最关键是兜帽、脸、沙漏、大钟轮的前后关系在侧视成立。

WeaponBuilder.FadeMaterial 证明项目有克隆调色板材质、修改透明 pass 的现成思路，但不能把它直接和 EnemyVoxelHit.shader 混用就视为透明已解决。透明版另需验证材质通道、受击反馈、深度与多层排序；本轮不新增 shader、不做全身多层 alpha 叠壳。透明不成立时保留上述实体版本，不依赖折射/体积雾/新API。

地形脚印建议 radius = 0.54m；高度筛选参考2.56m。单受击球中心 (0, 1.28, 0)、radius = 0.58m，material 暂用现有 soft 语义；背钟、指针和飘带不扩张主要受击范围。沙漏是否独立弱点暂不定，不能让装饰颜色暗示已经存在新破盾机制。

目标1,800–2,800实心格、10–14个可见volume，仍以3,000格为硬上限。先删次要小轮和飘带密度，再削主体厚度；不可把大钟轮的孔填满来省建模工作。预算不含尚未设计的攻击弹体；性能计数应另加弹体与特效，不能只报身体。

基色中的高光由光照产生，不增加第7色；同色不同PBR仍视作额外材质项，不能借此绕过上限。发光是材质自发光，不为每个核心/眼睛新增实时灯。

现有 WeaponBuilder 将160–191留给武器，EnemyVisual 使用200–223中的部分槽与239；它的200–239是敌人区间约定。新模型的12项可考虑集中申请224–235，但**这只是候选区段，不是已确认空闲**：实施前检查场景全部调色板写入与模型导入，初始化统一登记，不能按敌人实例反复覆盖世界共享槽。不要改旧200–223/239的色值去迁就新外观。普通体素材质必须保留世界调色板绑定，不用通用纯色PBR材质直接覆盖索引网格。

## 6. 体素编译规则与交接步骤

1. **先做同一个三维白模，后投三视图。**按上表中心、完整尺寸和挂点建立部件清单，颜色先只分身体/核心/护甲/连接件/功能件；同一部件ID贯穿三面。背环与顶环必须在白模就有真孔，不能等上色用暗色假画。
2. **独立部件各自编译整数格。**若包络最小角为 min、尺寸为 n×s，则局部格索引 i=0…n-1，格中心为 min+(i+0.5)×s；体积节点在 min，而 pivot 在独立挂点。尺寸尽量整格；对齐时从最小角统一取整，不能分别把中心和两端取整而改变厚度。武器“整数格代表中心”的数据可借鉴，但转换时保留其半格偏移，不能混用两套原点。
3. **形状用纯 Lua 判定。**盒体用XYZ区间；倒角盒从外层剔除角格；菱晶用 abs(dx)/rx + abs(dy)/ry + abs(dz)/rz ≤ 1；XZ顶环用平面内环带加Y厚度，XY钟环用平面内环带加Z厚度；齿块为固定12个轴向/阶梯段。实体壳按“外形内 - 内腔外”的差集，沙漏用分层变化截面。都是数值运算加 SetSolid，无须新引擎几何API。
4. **符文与石纹只做结构必要的线。**构装体手臂每侧一条折线；背板短锁孔；岩甲回纹等宽一格、必要时二格。相邻同色同刚性内容合并到同一网格；不要一符文一volume。独立动件之间留1–2格可见间隙；故意封闭的接缝让结构相交一格遮住，禁止共面重叠闪烁。
5. **优先平直体素与阶梯轮廓。**晶体、兜帽弧边、大钟环均以格子截面塑形；不要把大量小立方体各自任意旋转来造“体素感”。只对整只手臂/指针等刚性部件旋转。内腔用真正空格，不在透明壳里再塞一层完整表皮。
6. **纯数据编译后统计。**每部件导出 id、parent、pivot、min、dimensions、cells、paletteRole；cells存局部x/y/z和材质角色。总实心格≤3,000；volume数量、未合并暴露面数是预算估计，不能等同GPU draw call或帧率。超预算先并刚性件、删细碎装饰，再把s调整到0.10m；0.10m版本要重新统一取整与核对间隙。
7. **后续渲染适配只接现有方法。**在已有world里CreateVolume，写网格，设不可破坏/不可驱逐、碰撞层和掩码为0，RebuildGeometry一次，挂到正确pivot并补最小角偏移。长期保留volume句柄便于销毁；姿态只更新Node，不每帧重建、不把部件投进地形破坏接口。
8. **独立验收，再考虑玩法接线。**先用相同正交尺度给三面和两侧45°观察，检查真实深度/空洞/挂点/不透明灵体的可读性；再检查受击球是否覆盖有效身体。后续获准制作时只用项目约定的Web预览验收。当前文档不代表已做这些运行或画面检查。未定稿前不得改Spawner或替换现有敌人。

## 9. 遗迹战斗接线与动作

五只普通敌人各有一招普攻和一招技能。遗迹场景调用 `Spawner:EnableModelEncounters()` 加入五处遭遇。`EnemyModelAdapter` 构建带调色板的部件，`EnemyModelVisual` 以模型原始挂点为中心，逐帧应用各自的 `Config.posePart`。战斗期间只改变部件位置、旋转和缩放。

| 敌人 | 普攻 | 技能与躲法 | 受击与死亡表现 |
|---|---|---|---|
| 木灵 | 压低桶身后短冲头槌 | 四根扎地后沿锁定直线扑出，横移可躲，扑空后有停顿 | 树身扭动、两叶延迟摆动。死亡时树脂缩回，桶身前倒，两叶先后飘落 |
| 织巢虫 | 两只前钩向内交剪 | 张鞘后沿直线射出丝束，横移、起跳或借墙掩护可躲 | 合鞘抖领。死亡时六足内卷，甲鞘松落，金色茧囊缩瘪 |
| 岩甲巨兽 | 右侧大拳横扫 | 举拳砸地，冲击环由近及远扩散，跳过波前或退出范围可躲 | 肩胸错动并崩出岩屑。死亡时先跪落拆甲，肩晶最后落地 |
| 遗迹构装体 | 右臂瞄准后发射晶弹 | 双臂合拢，以橙线锁定方向，再发出青色窄束，可侧移或躲到墙后 | 胸晶后缩。死亡时双臂掉落，顶环随后坠下 |
| 时蚀灵体 | 钟针扫过前方扇区 | 停针后错位，在显形处延迟引爆圆环，可进入内圈、退出外圈或跳起 | 钟针受击回弹。死亡时钟环停转，灵尾与沙漏先消散 |
