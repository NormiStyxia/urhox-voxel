# 人物肘部绑定迁移（2026-11-14）

本轮只提供默认关闭的双肘数据、BlockCharacter 接口、离线证据及迁移清单。
脸、认可的头发层次、修长比例、服装设计均保留；没有拆膝，没有修改下列其他 owner 的模块。
结论依据：`docs/research/R6-动作绑定与武器路径动画.md` 的 B 路线。

## 数据与接口

- `BlockCharacter.USE_ELBOW_DATA = false` 为默认值；`BlockCharacter.LoadVoxelData()` 根据开关返回旧/新数据。
- 现有 `CreateVoxel(parent, explicitData, variant)` 继续完全尊重传入数据，开关不偷偷替换显式参数；旧调用方无需改动即维持旧模型。
- `nomi:HandSocket('right'|'left')` 返回角色拥有的掌心 Node，惰性创建、重复调用复用。无肘时归 arm，有肘时归 forearm；右节点名 SpellPalm、左 hand_left。
- 无肘时优先复用 arm 下调用方已经创建的同名挂点，保持其位姿；没有挂点才按当前掌心标定创建。历史 Blockbench Create 路径未提供体素掌心标定时返回 nil，不猜测新挂点。
- 挂点属于角色生命周期：调用方只挂自己的子节点，不修改/删除共享掌心；移除角色根节点时统一释放。
- 上臂仍叫 arm_right/arm_left，新增 forearm_right/forearm_left 为其子骨；两侧零旋转局部轴不镜像，前弯均为负 X pitch，不要给左肘反号。
- 基础 Update 把两肘归零，战斗/骑乘必须在基础 Update 后覆盖；不能把旧整臂角同时复制给上下段。

创建调用方在自己的初始化处改为：

~~~lua
-- 全部 owner 迁移并完成 Web 验收前保持 false。
BlockCharacter.USE_ELBOW_DATA = false
local data = BlockCharacter.LoadVoxelData()
local nomi = BlockCharacter.CreateVoxel(parent, data, BlockCharacter.SLENDER)
local palmR, palmL = nomi:HandSocket('right'), nomi:HandSocket('left')
~~~

开关不热替换存活节点。开关值确定后重新创建角色、战斗动画器和武器 rig；销毁旧角色前
先按现有释放顺序释放武器/特效。不要在每帧修改开关或重新 require 来试图改造旧实例。

## 轴心和挂点数值

测量来自生成源精修后的袖子/手部几何：双侧手部肤色 y=[29,35]，袖子最高 y=49。
袖段几何中部候选 y=42 向手侧半格移动到 y=41.5；在该截面量出闭环包围盒中心：
右 `(12.75,41.5,-1.5)`、左 `(-12.75,41.5,-1.5)`。这是宽袖绑定轴的几何选择，
并非可从低分辨率模型唯一反推出的解剖肘，不使用肩骨与手点的骨表中点。

原肩轴 ±9,46,-1.5；保留的掌心标定 ±19,33,-.75。
在当前 SLENDER 下、单位米：

| 局部向量 | 右侧 | 左侧 |
|---|---|---|
| 肩→肘 | (0.070125,-0.099,0) | (-0.070125,-0.099,0) |
| 肘→掌心 | (0.116875,-0.187,0.01518) | (-0.116875,-0.187,0.01518) |
| 肩→掌心（旧） | (0.187,-0.286,0.01518) | (-0.187,-0.286,0.01518) |

IK 应读取实际节点局部向量和长度，别把表中数值复制成另一份永久常量。两段长度约
0.1213m、0.2211m，宽袖的外轮廓不是骨长；正向弯折只演示负 X，侧向 pole 与腕朝向
由动作 owner 处理。挂点零肘角时世界位置/朝向连续，手掌仍位于原位置。

## 开启顺序

1. 保持开关 false，先把主场景、骑乘场景的加载入口和所有武器/施法挂点迁移到访问器，验证旧数据行为。
2. CombatAnim 增加可选两骨轨道、两骨解算、DebugSample 和补采样；WeaponRig 完成共享掌心生命周期迁移。
3. 在独立验收入口设置 true，重建角色，新增肘保持零角，确认原脸/头发/衣服/比例及所有挂点与旧模型一致。
4. 验收 45°/90°/120° 双肘、肩臂不脱节、外侧凹口与封口、正侧背视角、拉弓/下劈/骑乘；局部袖子几何方案如需改善必须继续在生成源中做，不能覆盖服装细节。
5. 完成 Web 实机渲染和性能验证后再决定正式开启；回退只设 false 并重建相关实例。当前没有打开开关，没有迁移其他 owner 的文件。

## 离线结果和边界

- 原 16 骨保持原 pivot/parent，新数据 18 骨。62,664 个半格面覆盖一致（15,666 个原单位格面）；原 8,079 个三角形裁剪后平面覆盖、方向和 RGB 的对称差面积为 0。
- 所有非手臂 quad/tri 数据逐行一致，palette 一致；零角旧外表面一致。新增的是静态内部封口，不能把“封口新增面”误报为外观变化。
- 双侧封口各 67.5 平方体素、未覆盖面积 0；掌心半径误差小于 4e-17m；左右均向 +Z 前弯，轴心不移。
- 弯折会形成外弯侧凹口。45°/90°/120°的对应边缘点最大分离为 6.97/12.88/15.78cm，**不是最短裂缝宽度**；肘邻域 552 个静态实体点中分别有 54/138/178 个不再落于两段实体。不能宣称全视角无缝、无透底。
- 已查看离线四角度×四视角预览；它不模拟引擎的剔除、光照和深度精度，真实引擎渲染与 Web 性能尚未验证。
- Lua 新绑定/旧默认行为回归通过。已有独立测试总计 31 项，本轮 29 通过、2 失败；失败均用 拆肘前原 BlockCharacter（blob f38bf8a63f4e9f8da6cb67461bd19fab074eecaa） 复现：tests/ruins/stream.lua 在 DragonStream.lua:54 缺 rings；tests/ruins/time_object_lifecycle.lua 在 TimeObject.lua:236 的 Dispose/RemoveVolume 生命周期检查失败。本轮不修改这些 owner 的模块，不将它们描述为全绿。
- 生成过程中发现新 SciPy 对等距 KD-tree 邻居的排序会影响原 polish 颜色投票。双肘分支重放既有 polish_edits.json 并核验 before RGB，避免重新投票改动认可头发；原基准和无参数生成路径未改。

证据：`art/nomi_voxel/elbow_preview/contact_sheet.png`、`checks.json`、`measurements.json`。
再生和离线测试命令见 `art/nomi_voxel/README.md`。
