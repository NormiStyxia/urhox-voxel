# 龙息着色器排查与预热（W6，2026-11-14）

## 结论与证据边界

针对 Windows 验收 `beb6e9f` 的 `hr=0x80004005` / `argument pulled into unrelated predicate` 和首次普通吐息约 2.06 秒尖峰，已做兼容性改写与预热。**没有 Windows 失败 shader 的名称、生成后的 HLSL 或编译器错误行；当前不能确认具体失败 shader，更不能把静态检查通过写成 FXC 修复已验收。**

源码中没有发现“非一致分支/循环内进行隐式采样或求导”的直接违规：

- `DragonStream.shader` 完全是 UV、sin、smoothstep 算术，没有纹理、导数、if、循环或 discard。不能据此将它定为导数问题根因。
- 普通吐息还有 `VoxelSprite.shader` 公告板粒子，以及 `DragonBreath:SpawnRing()` 使用的 `DragonRune.shader` 冲击环。后者不是 `DragonStream.shader`，但同样会在首次吐息命中时启用。
- 改前 `VoxelSprite.shader:19` 有本路径唯一的隐式 `texture(sprite_tex, UV)`，在所有分支之前；旧 23 行是包含 `||` 的 discard。采样位置合法，但仍把隐式导数带入 FXC 优化范围，改成 LOD 0 是可保持画面的防御性措施。
- 改前 `DragonRune.shader:159` 提前 discard，之后五次展开 `shape()`，其内含 style 分支、循环、`rune_band()` 提前 return；185–198 行又有嵌套调色分支和三处 discard。它没有采样/导数，属于需要复测的复杂谓词候选，不能声称已证明就是失败对象。
- 引擎生成的雾、灯光和 pass 代码不在这些 `.shader` 源码内；本次未改云、地面、树或全局渲染设置。

`assets/Materials/` 未发现以上 shader 的关联 XML；龙息材质由 Lua 构建。普通路径是 `DragonStream.New/Update` → `VoxelFX.Motes` / `DragonBreath:SpawnRing` → `MakeRune(style=2)`。光束、冰晶和经典平滑版本属于额外排查范围。

## 预热接线与限制

新增 `scripts/dragon/DragonShaderWarmup.lua`，官方 `generate_resource_meta` 已生成配套 `.meta`。`DragonStream.lua` 的 W6 标记仅在 4、23、53、79、136 行附近增加 require、字段、构造、Update 和 Destroy 调用；未改攻击、碰撞、伤害、瞄准、姿态和停止逻辑。没有修改 `RuinsDragon.lua`。

- 普通龙息对象创建后，连续 0.75 秒没有按住吐息、没有大招且帧长不超过 50ms，才提交一个预热对象；三个阶段之间分别再等待 0.75 秒。可以在骑龙前的空闲期完成。
- 依次是实际 CustomGeometry 吐息带布局、BillboardSet 粒子布局、实际 CustomGeometry 冲击环布局。不是仅 `SetSurfaceShader`，也不是隐藏/关闭的 Drawable。
- 网格克隆材质分别用 `strength=0` / `alpha_scale=0`；粒子使用真实贴图的透明边框 UV `(0,0)` 和透明顶点色。代理放在当前场景相机前，非零尺寸，关闭遮挡剔除与投影。一次最多一个极小代理，不创建碰撞或伤害。
- 至少保留两次 Update、观察到 `Drawable.inView` 后移除，再进行下一阶段。**inView 只证明有可见性/提交机会，不证明 FXC 编译成功。** 后端缓存命中与实际 draw 必须实机确认。
- 按住攻击或慢帧时暂停预热，不阻止玩家攻击。120 次提交仍未确认可见时停止并打印说明；Destroy 会清理代理。
- 预热将同步编译提前并分散到空闲帧，不能消除编译本身的耗时。如果玩家在完成前攻击、之后切换渲染/雾质量触发新变体、或编译失败，首次使用仍可能卡顿。没有宣称三种源材质覆盖所有后端/质量变体。

- Python `lupa.LuaRuntime` 执行 `validation/dragon-shaders/warmup_mock.lua`：PASS。空闲门槛、攻击/慢帧暂停、没有视口、三种几何布局、透明参数、源材质不变、一次一个代理、结束不重复、超时、Destroy、无冲击环分支。日志 `validation/dragon-shaders/warmup-mock.log`。只执行纯 Lua mock，没有启动 UrhoX。
- `python3 validation/dragon-shaders/lsp_check.py`：PASS，两个改动 Lua 文件 0 Error。日志 `validation/dragon-shaders/lsp.log`。
- `git diff --check`（仅本次文件）：PASS。日志 `validation/dragon-shaders/diff-check.log`。
- 人工 review：核对 source material Clone、Billboard 透明 guard texel、非零尺寸/相机/遮挡剔除、代理所有权/清理、攻击优先、共享文件最小补丁和分支边界。结果未发现上述检查范围内的遗留问题。

没有启动任何本地 Runtime，没有 build、commit、push。未验证 FXC/SurfaceShader 前端编译、真实渲染可见性、视觉等价性、实际 GPU 开销和 2.06 秒尖峰是否消失。移除冲击环提前裁剪会增加原本圆外像素的算术计算，实际开销需一起观察。

## Windows 实机复测

1. 使用相同 Windows D3D11/FXC 环境，记录版本、画质与雾开关。冷启动一次，保留完整控制台输出和帧时间记录；不要只截取 `hr` 那一行。
2. 龙出现/苏醒后不攻击，至少留出约 4 秒连续空闲帧。观察是否出现任何闪烁、黑点、白块或预热超时说明，并分别记录这段时间的编译和帧尖峰。
3. 骑龙 → 向空处按住普通吐息（检查 ribbon / billboard）→ 向地面或墙持续吐息并产生冲击环（检查 Rune）。随后松开再触发，并测试立即骑龙立即攻击的路径。
4. 核对控制台没有 `argument pulled into unrelated predicate`、`hr=0x80004005` 或其它 shader compile failure；对比第一次与第二次触发帧耗时，单独区分预热期卡顿和攻击帧卡顿。
5. 对照原画面检查吐息带、像素粒子、命中环、经典大招法阵的色彩/轮廓/抖动；切换画质后再测一次，避免仅验证缓存过的一种变体。
6. 若仍失败，保存错误前后的 shader 名、VS/PS、完整 define 组合、错误行、生成 HLSL（若日志提供）与触发阶段。只凭这个 HRESULT 和优化器文本不能继续断定某个源 shader。
