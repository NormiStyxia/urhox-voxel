# 武器图鉴 / 锻造台 UI 调研与第一版原型方案

日期：2026-11-17。基准：844×390 CSS 逻辑像素的手机横屏，同时兼容桌面。
结论：左侧独立 3D 展示间，右侧「三类标签 → 五档筛选 → 两列紧凑图鉴」，底部固定装备动作；用深色半透明墨幕、衬线标题、细金线与菱形建立层次。

## 0. 证据边界与项目约束

- **下文全部产品观察为凭记忆、未核实**：未取得可用页面、截图或录屏，不能视作当前版本逐项验收。动效毫秒、缓动、粒子预算全部是本项目建议值，绝非产品实测。
- 联网尝试：[原神 Inventory](https://genshin-impact.fandom.com/wiki/Inventory) 返回 `ERR_ADDRESS_UNREACHABLE`；[MHW Iceborne 装备手册入口](https://www.monsterhunter.com/world-iceborne/us/playguide/manual/en/ps4/large/gear.html) 浏览器连接超时，路径与内容均未核实。两条仅是失败读取记录，**不作为论据来源**；没有为其他产品补造来源链接。
- 项目内已存在的设计依据：[R14 稀有度分级](R14-稀有度分级命名与产品对照-2026-11-17.md)。本稿沿用其五色；品质增加外观与展示仪式感，不增加攻击力、范围或能力。
- 武器大类固定为近战 / 弓箭 / 法器；没有部件编辑、词条洗练、强化数值或锻造配方。本页从锻造台打开，但首版主要完成浏览与装备。
- 3D 武器本体保留自身配色；稀有度色用于 UI 和展示光，不给整把武器强制染色。

## 1. 成熟产品：每款可取的一点

下表各行均为「未核实」；同系列与不同输入平台会有差异。

| 产品 / 页面 | 信息组织与交互观察（未核实） | 对本项目的结论 |
|---|---|---|
| 原神：武器 / 背包 | 武器分类、图标格、稀有度底色与星数让浏览很快，选中后集中呈现物品信息；详细武器页突出模型与养成入口。 | 借鉴分类和明确焦点，但重排成左模型右图鉴，不搬入整套等级、精炼、突破。 |
| 崩坏：星穹铁道：光锥 / 遗器 | 光锥主要靠插画、星级和详情识别，遗器还需要部位与属性筛选；同屏有稳定的选中详情区。 | 借鉴筛选位置稳定、选中后详情不乱跳；光锥不是可旋转实体武器，不能作为模型换场依据。 |
| 鸣潮：武器 | 图标格与武器详情共同服务装备和养成，星数 / 品质底卡帮助快速扫视。 | 使用清晰的三类入口与图鉴格，养成标签不进入首版。 |
| 明日方舟：干员 / 模组装备 | 干员卡与职业过滤擅长大量对象浏览，模组属于干员详情中的另一层信息。 | 借鉴高对比标签、切角和选中标记；不要把干员星数、职业及模组解锁条件直接套成武器规则。 |
| Diablo IV：物品 tooltip | 名称品质、分类、属性与特殊效果有强文字层级，密集属性适合比较但容易占屏。 | 只保留名称、类别、品质、外观说明四层；手机使用点击展开说明，不依赖悬停。 |
| Path of Exile：物品 tooltip | 名称色、分隔线和分组词条帮助阅读复杂物品，Unique 与 Rare 不是简单逐级更强关系。 | 学分组和分隔线，不照搬其颜色阶序或密集词条；本项目五档独立定义。 |
| Destiny 2：Inspect / Collections | Inspect 服务单件细看，Collections 服务分类目录，两种浏览目标有所分工；武器轮廓与大图有强识别性。 | 保留一个固定模型舞台，收藏筛选属于图鉴；不放入插槽、perk 组合和完整改装页。 |
| Monster Hunter World / Rise：武器选择 / 锻造树 | 武器类型与装备列表适合快速选择，锻造树解决前置、分支和素材关系，复杂度随路线增长。 | 借鉴类型入口和模型预览；当前没有升级路线，首版不用树形结构，也不把两作当完全相同界面。 |
| 艾尔登法环：装备 / 武器菜单 | 装备槽、物品列表、属性需求与说明层级清晰，但菜单阅读密度偏高。 | 学「浏览高亮」与「实际装备」分离；不用大量属性列占用手机展示空间。 |
| 塞尔达：旷野之息 / 王国之泪：武器栏 | 临时横向选择条适合战斗中快速切换，完整背包格支持更多管理；耐久与破损承担实际玩法意义。 | 图鉴使用网格，把轮播留给后续快捷入口；当前项目没有耐久需求，不新增耐久条。 |
| Hades：武器 aspect | 先选武器再选形态，有限选项与明确解锁 / 当前选择反馈形成层次。 | 学「类型 → 具体外观」的两级路径与确认动作；不引入影响技能的形态升级。 |
| Warframe：武器库 | 装备槽、武器选择与外观 / 升级入口分层，预览服务当前配装对象。 | 学当前装备状态与浏览对象区分；不把 MOD、极化、容量等系统带入图鉴。 |

### 信息架构选择

| 形式 | 优势 / 问题 | 本页取舍 |
|---|---|---|
| 单列列表 | 长名称、说明容纳好，但 390 高度下同时看到的武器少。 | 窄屏 / 辅助阅读模式回退；不是 844 横屏默认。 |
| 两列紧凑网格 | 844 横屏右区可同时看 6 把，横向比较快，能留住大模型舞台。 | **首选**；卡内是缩略图 + 两行文字，不是另一个大展示窗。 |
| 横向轮播 | 一次聚焦少数物品，逐个寻找成本随数量上升，还会与模型旋转手势冲突。 | 不作为图鉴主结构；留给以后背包快捷切换。 |
| 锻造树 | 直观表示升级前置与分支，但对纯外观目录增加无效复杂度。 | 等真实锻造路线出现再单开页面。 |

顺序固定：全局返回 / 标题 → 近战、弓箭、法器 → 全部、普通、优秀、稀有、史诗、传说 → 结果网格 → 固定装备按钮。
排序首版固定按品质降序、同品质按稳定 ID；装备、新获得、收藏均不实时把条目挪位。各类别记住最后浏览项与滚动位置。
更换筛选后：当前项仍在结果中则保留；否则选择首项但不装备；结果为空则清空预览并显示「此分类下暂无武器 / 清除筛选」。
未获得条目可以浏览轮廓与说明，按钮显示「尚未获得」并禁用；筛选结果数量同时报可用与未获得数量。

## 2. 切换动效与推荐参数

默认三条原则：模型淡化与微移、界面只动一次、连续点击最后一次生效。所有值为原型建议，可通过真机调整。

| 对象 / 触发 | 时长与缓动 | 表现 |
|---|---|---|
| 卡片按下 / 松开 | 按下 70ms、松开 100ms；ease-out | 仅缩略图 1 → 0.98 → 1；边框不缩，保住触控目标。 |
| 选中态转移 | 120ms；cubic-bezier(.22,1,.36,1) | 旧细描边退去，新卡出现金色四角与选中菱形；不把整张卡撑大。 |
| 同类切武器 | 旧 0–90ms 淡出；新 90–250ms 淡入；出 ease-in、入 ease-out | 展示根节点微移 6px / 8px，舞台、相机与背景不切场；淡入结束即稳定。 |
| 切大类 | 0–100ms 旧内容退去；100–280ms 新内容进入；ease-out | 指示线 160ms 横移；网格整体 8px 微移，不给每格叠加长延迟。 |
| 品质展示光 | 新模型换入后的 90–250ms；ease-out | 仅局部光圈淡入；史诗 / 传说可带一次短粒子，避免白屏或全屏爆闪。 |
| 稀有度筛选 | 120ms；ease-out | 立即更新数量，网格淡变；不触发类别切换演出。焦点留在筛选按钮。 |
| 装备成功 | 状态立即确认；标记 160ms 入场；提示 1200ms | 当前卡出现勾与「已装备」，按钮同步；提示不挡模型和下一次点击。 |
| 旋转回正 | 260ms；cubic-bezier(.22,1,.36,1) | 从当前角度走最短角回默认展示姿态，禁止绕一整圈。 |
| 减少动态效果 | 0–80ms 淡变 | 关闭自动旋转、位移、惯性、光脉冲与粒子；保留状态标记。 |

### 模型换入时序与异步保护

| 时间 / 事件 | UI | 展示间 |
|---|---|---|
| t=0 点击 B | `selectedId=B`；同步名称、品质、获得状态；更新卡片描边。 | 发起 B 资源请求并标记 requestId，当前 A 立即进入淡出。 |
| 0–90ms | 可继续选 C，不锁列表。 | A 淡出；统一展示根节点接管旋转和模型归一化。 |
| t=90ms，B 已就绪 | 装备动作只针对 B。 | 移除 A；B 从透明 / 8px 偏移进入。 |
| B 尚未就绪 | 预览区显示 B 的缩略图；超过 150ms 才显示加载标记。 | 不再显示能被误认成 B 的 A；B 就绪后执行 160ms 淡入。 |
| t≈250ms（缓存命中） | 选中状态稳定。 | B 完成展示；传说短粒子最多再持续 180ms。 |
| 快速点 C / 返回 / 模型失败 | 仅最新 requestId 能写入；错误只作用于当前物品。 | 取消旧动画 / 忽略迟到结果；失败保留缩略图和重试，不让旧模型重新出现。 |

3D 阶段用模型透明度、展示根节点与灯光控制；**不要为了做 HTML 原型提前假定引擎已有透明淡化材质支持**。HTML 占位使用同一时序；引擎接线再验证材质，必要时以短暂遮罩淡变替代。
切新武器恢复该类默认姿态；同一武器内部筛选 / 收藏 / 锁定不重置旋转。预览资源加载失败不等于物品未获得，装备可用性由业务数据决定。

## 3. 五档稀有度：颜色之外也能区分

色值沿用 R14，是项目设计值，**不是竞品取样色**。卡片保持共同暗底；品质色只占卡底局部、短边和标签，避免五彩大色块争抢模型。

| 品质 / 色值 | 卡片底与边框 | 舞台背景光 | 数量标识 / 额外特征 | 选中光效与粒子 |
|---|---|---|---|---|
| 普通 `#A8AFBA` | 中性暗底、1px 单线，底部淡色条。 | 中性轮廓光，无品质光圈。 | 1 颗实心菱形；简洁平直边角。 | 固定金色选中角标；无粒子。 |
| 优秀 `#4FCB78` | 底部 6% 品质色晕，1px 线加短角线。 | 很窄的柔光，避免染绿整把武器。 | 2 颗菱形；两侧短刻线。 | 同样选中角标，附一次 120ms 柔亮；无常驻粒子。 |
| 稀有 `#4C9DFF` | 底部 9% 色晕，单线加内侧短高光。 | 一道薄光环 / 局部背光。 | 3 颗菱形；顶部小型对称饰线。 | 一次 200ms 光扫；换入最多 4 枚短粒子。 |
| 史诗 `#B978F4` | 底部 12% 色晕，局部双线，四角有切面。 | 两段不闭合光弧，亮度略高。 | 4 颗菱形；侧面增加一组断续刻度。 | 300ms 局部光环；换入最多 8 枚短粒子。 |
| 传说 `#F5A23D` | 底部 15% 色晕，局部双线加单个冠形菱饰。 | 一个独特断裂时间环，避免堆多圈。 | 5 颗菱形；顶部专属徽记，保持卡片高度不变。 | 350ms 短环显现；换入最多 12 枚短粒子，低画质归零。 |

- 菱形统一表示品质数量，不同时叠加五颗星；品质文字始终保留，色觉差异和灰阶下也能判断。
- 金线表示**当前浏览选中**，品质色表示**物品品质**；传说卡另有实心选中菱形，不能靠橙 / 金色差判断。
- 装备勾、NEW、锁、收藏使用固定位置和不同符号，不参与品质装饰递增。
- 图鉴格禁止常驻流光 / 常驻粒子；昂贵光效只在左展示间出现，停留后稳定。首版不叠加持续脉冲。
- UI 框线保持 1px，品质增强主要靠角饰、内线、光纹，不逐档把边框加粗成方盒。
- 正文使用稳定浅色，不直接用五种品质色写小字；最终对比度以真实背景截图检查。

## 4. 浏览、装备与标记的状态模型

状态不能压成单一枚举：`selectedId` 是浏览焦点；`equippedIds` 来自装备规则；每件物品另有 `owned/locked/isNew/favorite`；模型另有 `idle/loading/ready/error`。
装备槽是一处还是每类一处，应接现有玩法数据；HTML 数据适配层允许两种模式，不由切换标签暗中决定装备规则。品质只是展示元数据。

| 触发 / 前置 | 状态变化 | 可见反馈 / 边界 |
|---|---|---|
| 点击卡片 | 修改 selectedId；不改变 equippedIds。 | 卡片金角 + 左侧预览；原装备勾保留。 |
| 点击「装备」，已获得且非当前装备 | 本地原型立即成功；真实接线进入 pending，请求成功后更新装备数据。 | pending 显示「装备中」并防重复提交；成功标勾，失败提示并恢复旧装备。 |
| 浏览当前装备 | 不变。 | 按钮显示「已装备」并禁用；仍可旋转 / 收藏。 |
| 装备 pending 时浏览别件 | 可改 selectedId；pending 绑定提交时的物品 ID。 | 请求完成按该 ID 更新标记；不得给后来浏览的物品错标已装备。 |
| 尚未获得 | 可选中、可预览；不能装备。 | 「未获得」覆盖标，缩略图降低饱和度；按钮「尚未获得」。 |
| 点击锁 | owned 时切 locked；与装备、浏览独立。 | 锁闭 / 锁开，轻提示；锁不阻止装备和切换。 |
| 点击收藏 | owned 时切 favorite；与锁、装备独立。 | 实心 / 空心收藏标；当前列表不重新排序。 |
| 获得新武器 | owned=true、isNew=true。 | 右上 NEW；类别入口可显示新获得数量。 |
| 新物品详情完整可见 500ms | isNew=false；未获得物品不适用。 | 淡出 NEW；快速掠过不清除，装备不是清除的必要条件。 |
| 切类别 / 关闭重开 | 保存各类浏览与滚动；装备状态不变。 | 首次进入优先选本类已装备项，否则首个已获得项；全未获得时选首项，空目录显示空态。 |

原型中的锁只演示保护状态；当前没有分解 / 出售操作，不展示不存在的按钮。后续有破坏性操作时再消费 locked 条件。
卡片建议固定：左下品质菱形，右下装备勾，右上 NEW；锁 / 收藏放详情动作条，卡内只显示小状态图标。
NEW 与选中无障碍文本同时存在；选中不靠发光、已装备不靠颜色；锁 / 收藏的触控按钮均有文字标签。

### 3D 展示交互参数

| 交互 | 建议实现 |
|---|---|
| 初始姿态 | 每类一个可配置三分之四展示角；剑 / 弓 / 法器按包围盒居中与缩放，保持 12–16% 舞台边距，不改真实资产尺寸。 |
| 拖拽 | 仅在左舞台触发；移动超过 8px 才判拖拽；水平 0.35°/px 控 yaw，垂直 0.18°/px 控 pitch，pitch 限 ±20°。 |
| 惯性 | 松手角速度上限 75°/s；每秒按 exp(-7×dt) 衰减，低于 1°/s 停止；deltaTime 单位秒。 |
| 回正 | 双击间隔 ≤280ms、两次位置距离 ≤20px，且两次都无拖拽；260ms 回正；另提供 44px 可见回正按钮。 |
| 自动旋转 | 无操作 4s 后以 6°/s 恢复，仅绕 Y；界面初次稳定后也等待 4s，首次用户拖动前不突然抢控制。 |
| 手动操作优先 | 任意舞台 pointerdown、回正、切武器均取消惯性并重计 4s；只在页面可见且模型 ready 时更新。 |
| 暂停 / 无障碍 | 展示间有暂停自动旋转开关；减少动态效果时默认关闭旋转与惯性。 |
| 资源 / 场景 | 切武器复用展示间、相机、灯光；旧模型释放或进入有限缓存，不在列表滚动时加载全部 3D 资产。 |

首版 HTML 若使用 2D 图 / 占位模型，明确标「展示占位」；二维 rotate 只能验证指针响应，不能宣称已验证真实 3D 光影、惯性轴或材质。

## 5. 横屏手机与桌面适配

- 所有尺寸使用 CSS 逻辑像素，844×390 不是物理像素；不按 DPR 缩小控件。安全边距为 `env(safe-area-inset-*) + 设计留白`。
- 基准左右留白 16px、上下 8px；全面屏左右挖孔会进一步缩减内容区，不能把按钮塞进挖孔范围。
- 标签 / 过滤 / 工具按钮命中区至少 44×44px；品质筛选视觉高 36px，可在上下各扩 4px，和列表留出分离区，命中区互不重叠。
- 卡片 56px 高，列间距 8px、行间距 6px；锁、收藏不在格内塞多个小点击点，详情动作条给独立 44px 命中区。
- 字号：页面衬线标题 22px；武器名 / 按钮 16px；列表与正文 14px；辅助标签最低 12px。行高 1.35–1.5，中文长名两行或省略后在详情完整显示。
- 列表纵向滚动；**上下滑不切类别**。首版左右滑不切武器，舞台横拖专门控制旋转，避免同一手势两种意义。
- 后续若加左右切换，只能在明确的武器名条 / 上一把下一把区域实现；水平位移 ≥48px 且水平 / 垂直位移比 ≥1.5，不能覆盖舞台与网格。
- 桌面鼠标拖拽等同触控；可聚焦按钮，类别 / 过滤使用 tablist 与方向键，网格用方向键移动，Enter 装备，Esc 返回。不可用悬停承载必读说明。
- 展示区使用 pointer capture；`touch-action:none` 仅用于舞台；列表保留 `pan-y`。双击回正后屏蔽后续误判拖拽。
- 页面根布局锁在可用视口高度，只有结果区滚动；底栏始终可见，内容不被底栏覆盖。
- 桌面内容宽度建议上限 1440px，左舞台 48–54%，右侧最多 3 列；不得把武器卡无限拉宽。
- 净宽不足 760px 时按卡片最小宽 180px 回退一列；低于 640px / 竖屏时上下排：舞台 140–180px，下面分类和列表，允许页面滚动，保留底部装备栏。
- 净高不足时减少可见行，优先留住分类、过滤、至少一行卡片与装备入口；不统一缩小整页。320px 宽仍可单列阅读。

### HTML 第一版实现清单

| 必须实现 | 完成标准 |
|---|---|
| 单页布局 | 844×390 无横向溢出；桌面、刘海安全区、320px 单列均可阅读。 |
| 真实状态原型 | 三大类、全部 + 五档过滤、每类各五档以上的模拟数据；选择与装备分离。 |
| 非理想状态 | 无结果、未获得、模型加载 / 失败占位、超长名称、快速连点、装备失败模拟。 |
| 品质体系 | 五色、1–5 菱形、五档角饰；金选中角、装备勾、NEW 不混淆。 |
| 展示占位与接口 | 优先复用已有合规资产 / 模型；没有模型时用明确占位，预留 select / load / rotate / reset 接口。 |
| 基础交互 | 点选、装备、锁、收藏、NEW 延时清除、记住分类浏览；模拟数据用版本化 localStorage，可一键重置。 |
| 轻动效 | 表中 120/250/280ms 时序、最后一次选择生效；加载失败仍能浏览其他条目。 |
| 输入与减少动态效果 | 44px 触控、键盘焦点、可见回正 / 暂停；prefers-reduced-motion 生效。 |

| 首版暂不实现 | 原因 / 接线条件 |
|---|---|
| 部件、强化、属性比较、耐久、锻造树、材料消耗 | 当前浏览 / 外观装备范围没有这些玩法，不先造入口。 |
| 真实背包改写 / 网络装备请求 | HTML 先验证布局与状态，实际装备适配项目现有槽位规则后再接。 |
| 新生成全部武器模型 / 图片 | 不因页面占位扩大美术制作范围，沿用已有资源。 |
| 全屏粒子、持续流光、逐卡入场、复杂转场 | 低横屏高度中干扰识别，还增加真机性能与验收成本。 |
| 全库检索 / 多重排序 / 长按菜单 | 首版武器量有限，先验证三类与品质过滤；收藏先做标记，后续再加独立筛选。 |
| 用 2D 伪旋转当作真实 3D 验收 | 光照、包围盒、模型轴、材质透明度与资源释放需要实际展示间验证。 |

原型验收按「打开 → 切法器 → 筛传说 → 点选 → 装备 → 切回近战 → 返回法器」跑一轮，确认选中记忆、装备勾与筛选都符合状态表；再跑空结果、快速连点、加载失败、减少动态效果和 320px 回退。
验收口径：HTML 能证明布局和交互；模型视觉必须在项目既定 Web 预览中读取实际画面后另行判断，本调研不启动预览或远端构建。
