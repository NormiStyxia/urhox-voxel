# R14：Minecraft 动作类战斗模组的近战手感调研

日期：2026-11-18

本轮由 maker GPT 供应商的 GPT-6.1-Sol 研究任务完成资料检索，并结合当前项目的 CombatAnim、CombatMoves、WeaponRig 与 EnvironmentDamage 接线做对照。没有修改游戏代码。

## 结论

Minecraft 动作模组的近战不僵硬，核心不是把动画播放得更快，而是把一次攻击拆成几个互相独立、互相配合的时序。

1. 输入接受、攻击承诺、命中判定、动作收束和下一次输入分别有边界。
2. 每一段连击都有自己的动作形状、命中形状、命中时刻、移动速度和攻击角度。
3. 身体、根节点和武器轨迹一起运动。手臂只是结果的一部分，不能让上半身挥动而双脚和根节点完全冻结。
4. 命中反馈只在命中窗口触发，并且会短暂改变攻击者或受击者的姿态、速度和镜头。空挥也有收束，不会停在一个等待状态。
5. 连击允许在当前动作完成前接收下一次输入，但只在明确的取消窗口兑现。这让玩家感觉动作连续，同时保留每段攻击的承诺感。

当前项目已经有 hit_on、hit_off、cancel_open、cancel_close 和五段片段。僵硬感主要来自三个位置。

- 每段动作的根运动很少，身体重量大多由手臂与武器轨迹表达。
- 命中窗口与刀刃轨迹虽然都存在，但身体转向、脚步和武器路径没有形成同一个“经过目标”的运动过程。
- 连击输入与下一段动作的衔接更像片段排队，缺少可提前读取、在取消窗口无缝接续的输入缓冲。
- 空挥、命中、受击三种结果的收招差异不够明显，玩家会看到同一种停顿。

## Better Combat

Better Combat 的公开源码把武器属性和一次攻击拆成数据结构。武器可以指定待机姿势、单手或双手、武器类别和连续攻击序列。每个攻击段又单独指定命中形状、伤害倍率、攻击期间的移动倍率、攻击范围倍率、扇区角度、命中时刻和攻击动画。

这套结构解决了“所有武器都用同一个挥刀”的问题，也解决了“动画看起来到了，判定却在别的时刻发生”的问题。源码注释明确要求把 upswing 命中时刻对齐到动画的 tipping point，也就是武器真正经过目标的临界点。

Better Combat 的输入管理器还把持续攻击、当前挥击、连击重置、攻击与挖掘的输入策略、目标缓存分别保存。攻击不是每次点击都从零开始，也不是按键后立即把整段动作锁死。输入会先进入当前挥击状态，再按照冷却和连击序列决定下一次攻击。

对本项目最有价值的是数据拆分方式。

- sword_light_1 到 sword_light_5 需要各自拥有命中角度、命中形状、移动倍率和命中时间。
- 第一段可以是横向斩，第二段可以是反向回斩，第三段可以是前压斜斩，第四段可以是收身反手，第五段才使用更宽的终结动作。
- 命中点应来自刀刃轨迹的峰值，而不是固定使用同一帧的中心点。
- 攻击期间允许有限的朝向修正和短距离根运动。移动倍率在起手和收招较低，在穿过目标的主动段较高。
- 连击输入缓存应只保存下一段意图，命中窗口内不立即重启当前片段。

## Epic Fight

Epic Fight 把攻击动画注册为 ComboAttackAnimation，每段连击是独立动画对象。官方 API 示例中的三段三叉戟攻击使用不同的时间参数，三段的起手、命中和收束位置不同。连击不是一个长动画里换几个手臂姿势，而是多个可以被战斗系统识别的攻击段。

Epic Fight 同时把生活动作、走路、跑步、跳跃、瞄准和战斗动画放入同一个 Animator。攻击片段因此会与移动和朝向状态切换，而不是只覆盖两条手臂。它还通过实体补丁和战斗行为把敌人追击、攻击和动画连接起来，让敌人的动作承诺也有对应的时序。

对本项目最有价值的是“战斗层与生活层共享身体状态”。

- 攻击前保留当前移动方向和身体朝向，起手时允许身体先转，手臂后跟。
- 主动段用根运动或很小的前移表达重量，脚步和根节点需要有连续位移。
- 收招时恢复站姿，下一段从上一段的结束姿态进入，不能每段都从同一个待机姿态开始。
- 受击、闪避和落地应作为高优先级动作层打断或替换攻击层。攻击层被打断时要有明确的被打断姿态，不能只把时间轴清零。

## Minecraft 动作战斗的共同做法

Better Combat 和 Epic Fight 的实现重点不同，但它们都把攻击段看成带时间和空间的动作。

- 攻击不是瞬时事件，而是有起手、主动、收招。
- 命中箱跟随武器或攻击方向变化，而不是一直固定在角色前方。
- 不同武器和不同连击段可以使用不同的范围、扇区、移动速度和命中时刻。
- 输入在攻击期间仍然有效，但只会在可取消阶段转化为下一段。
- 角色朝向、根运动和攻击动画共同决定玩家是否感到动作有重量。
- 视觉反馈和伤害反馈同一时刻发生。刀光、音效、受击反应和短停顿不能相互错开太多。

这些做法与“把每一段动画加速”不同。单纯缩短片段会减少承诺感，却不会解决根运动冻结、攻击段之间姿态断裂和输入衔接僵硬的问题。

## 对当前五段剑连击的具体诊断

当前 AnimClips.lua 已经有片段阶段和命中事件，属于正确方向。问题在于动作内容和状态衔接。

### 起手

现在起手主要依靠上臂、前臂和武器姿态变化，身体根节点参与不足。角色看起来像把手臂摆到位置，而不是从身体带动刀刃。

建议每一段加入小幅身体先导。

- 身体朝向先于刀刃约 20–40ms。
- 前脚在起手末端产生很小的承重位移。
- 起手期间允许角色朝输入方向转向，但转向速度随动作进度衰减。
- 起手不能有伤害和体素破坏，仍保留现有 hit_on 边界。

### 主动段

命中应该落在刀刃速度最高且刀尖经过目标的时间点。当前环境破坏已经使用真实刀根和刀尖，但敌人命中、体素破坏、刀光和音效仍需使用同一个主动段时间。

建议每段保留一到两个主动子窗口。

- 第一个子窗口用于刀刃进入目标。
- 第二个子窗口只在刀刃继续穿过目标时使用，避免一帧内重复伤害。
- 体素横向切带继续限制在原始命中体积和玩家视线内。
- 弓和法器不复用剑的主动窗口。

### 收招

收招是当前最容易显得僵硬的部分。攻击结束后角色需要从刀刃终点姿态自然回到下一段或待机姿态，不能马上把根节点和双臂重置。

建议把收招拆成两个状态。

- recovery_soft 允许提前读取下一次攻击，但只接受移动和朝向修正。
- recovery_commit 继续保持刀刃终点姿态，直到取消窗口开放。
- 下一段从上一段的终点姿态开始，使用短淡入，不从 stance_combat_sword 重新起步。

### 输入缓冲

Better Combat 的持续攻击体验来自输入缓冲和连击序列，而不是让玩家精准点击每个窗口。当前项目应保留单次点击的节奏，同时增加一个很短的缓冲。

建议初始值：

- 输入缓冲窗口 120–180ms。
- 只缓存下一段，不叠加多段。
- cancel_open 前输入只记录，不切换动作。
- cancel_open 后立即消费一次缓存。
- 受击、倒地、跳跃和武器切换清除缓存。
- 松开鼠标不取消已经进入主动段的攻击。

### 命中反馈

Minecraft 模组的重量感来自命中时刻的共同反馈，不是来自更长的后摇。

建议把当前反馈拆成三个等级。

- 空挥，短促刀风、轻微身体回弹，不触发敌人停顿。
- 普通命中，目标短暂停顿，攻击者只保留很短的刀刃停顿，镜头轻微沿挥击方向移动。
- 破韧或重击，目标较长硬直，攻击者保持终结姿态，镜头和音效升档。

体素破坏的事件反馈应跟随实际 VoxelDamaged.Removed，不能把原生 ApplyDamage 返回值当作伤害格数。隔墙、地面和弓单格保护继续放在环境伤害层。

## 最小改动顺序

1. 先改五段动作的终点衔接。让第 n 段的终点作为第 n+1 段起点，减少每段回到待机的断裂。
2. 增加 120–180ms 的单段输入缓冲和 cancel_open 消费规则。
3. 为五段分别添加小幅根运动和身体先导，控制在角色半身宽度以内。
4. 把敌人命中、体素破坏、刀光、音效统一到同一个主动子窗口。
5. 再调命中停顿和镜头反馈。先区分空挥、普通命中和破韧，保持现有性能预算。
6. 最后才调每段的范围、角度和横向切带宽度。

## 验收建议

每段需要录制以下场景：

- 原地连续五段，观察上一段终点到下一段起手是否断裂。
- 连续点击速度高于攻击速度，确认只缓存一段且不会丢输入。
- 攻击中转身，确认前半段有转向、主动段承诺方向、收招不瞬移。
- 空挥、命中普通敌人、命中硬目标各一次，比较停顿、音效和刀光。
- 低帧率跨过 hit_on 或 cancel_open，确认不会漏伤害或重复伤害。
- 刀刃切体素时检查真实刀根/刀尖轨迹、隔墙、地面和弓单格保护。

建议记录每段的输入时间、动画时间、根节点位移、刀根/刀尖位置、命中事件、受击事件、体素事件和帧长。动作是否顺滑需要看这些时间是否同一套时钟推进。

## 证据边界

Better Combat 的武器参数和攻击管理来自公开 GitHub 源码。Epic Fight 的连击动画注册和 Animator 接线来自公开 API 文档。Minecraft 模组的具体默认数值随版本、武器数据包和配置变化，本文不把示例参数当作当前项目的最终数值。
