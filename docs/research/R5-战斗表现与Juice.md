# R5：战斗表现与 Juice

日期：2026-11-14。只读对照主方案全篇、R1 及指定战斗/敌人/HUD/TimeSpells 模块；未运行游戏。本文是建议，**不替代主方案 §14–17 的裁定**。以下来源访问日期均为 **2026-11-14**；官方、开发者自述、社区资料与我的推断分别标注。竞品没有公开的镜头米数、粒子数、音效帧点均为“未确认”，参数表全部是本项目待 Web 验证的起点。

## 10 条可执行结论

1. 用同一命中事件同步接触闪光、材质音、局部顿帧、受击姿态；空挥只播破风。
2. 做软体、硬甲、弱点、破甲四套反馈；区别首先来自形状和声音，其次才是颜色。
3. 保留轻击 0.04s、重击 0.08s、破甲 0.10s；同一挥击群攻只取最大顿帧。
4. 碎屑从真实接触点沿斩向喷出，替换身体中心均匀撒粒；先保持每击 6–10 粒。
5. 刀光用 6–8 段阶梯带，跟随刃根/刃尖；只覆盖活动段及其后 0.06s。
6. 满蓄力只提示一次：弦/剑刃收光、短闪、提示音；持续持有不反复爆闪。
7. 倒地做失足—侧倒—触地—挣扎—起身，取消整体压扁；Boss 普通受击不滑步。
8. 手机镜头先保双方和地面预警可见，再加轻震；普通箭不拉动远处射手的镜头。
9. 血条加短延迟损血条，命中准星短收拢；伤害数字保持默认关闭，破甲图标常可读。
10. 沿用共享 64 粒上限，另管刀光、光环、法术尾效和音频声部；池满降装饰，不丢预警。

## 分专题详述

### 1. 怪猎：让“打到哪里”改变反馈

**社区资料：World 的 Kiranico**区分肉质、部位破坏、畏缩与异常阈值；部位损坏可能改变弱点或攻击覆盖，并非每次命中都会倒地。**官方：Wilds**集中模式高亮伤口/弱点，集中弱点攻击破坏伤口并造成大伤害、使怪物受控。两者支持“认出部位→集中攻击→可见破坏→输出窗口”的闭环，不能混称一套伤口机制。

来源：[World / Kiranico](https://mhworld.kiranico.com/guide/understanding-monster)（社区）；[Wilds / Focus Mode](https://www.monsterhunter.com/wilds/en-uk/hunting/focus-mode/)（官方）。访问：2026-11-14。

**官方：Rise/Sunbreak 手册**分别提供玩家/他人命中特效、镜头震动开关、相机距离设置；说明表现强度和构图需要可调，而不是所有效果常开最大。读取官网本地化正文 `Basic Info/Options` 的对应条目，未取得其具体强度百分比。**Now 官方狱狼龙指南**明确：虫落点发红光预告落雷，发光状态中的大声咆哮预告强攻击，蓄能时侧面落雷而头尾可攻击；身体状态、地面危险和安全输出位置一起传达战术信息。其通用预警时长、顿帧和相机参数**未确认**，不沿用 World/Rise 的帧数。

来源：[Rise 官方手册正文](https://game.capcom.com/manual/MHRISE/locale/data/en.json?t=202204201000)；[Now / 狱狼龙指南](https://monsterhunternow.com/en/monsters/stygianzinogre)（官方）。访问：2026-11-14。

**我的推断：**石甲兽硬甲用扁平白火星＋清脆石金属音，核心用小十字亮核＋晶体音；破甲额外增加几块有方向的甲片，背甲真正隐藏后露核。狂暴只改变姿态、节奏和裂缝亮度，不能顺便免费开甲。硬甲仍正常结算主方案伤害，不新增强制弹刀规则。

### 2. 时间、空间与节奏：原神、鸣潮、死亡细胞、Hi-Fi Rush

**社区实测：KQM**将 hitlag、hitmark、recovery 分开；原神剑前两段基础 hitlag 为 0.03s，未破韧可另加 0.06s；普通弓射常为 0，蓄力爆头列 0.12s。它支持按事件分级，不能把某个数字当全武器标准。**社区：鸣潮攻略**记录黄圈汇合的弹反提示、精准闪避慢时间，以及协奏满时的高频提示音；这些反馈在传达“现在能做什么”。

来源：[KQM / Frames](https://library.keqingmains.com/combat-mechanics/frames)；[GuildJen / 鸣潮](https://guildjen.com/wuthering-waves-combat-guide/)（均为社区）。访问：2026-11-14。

**社区：死亡细胞**的 Breach、Stagger、Knockback 分别表达打断、判定延迟和位移，普通 Breach 不适用于 Boss。其橙色损血段具有可恢复生命的玩法语义，不能照搬后让玩家误以为能吸回血。**官方产品说明：Hi-Fi Rush**明确角色、敌人攻击、环境与音乐同步；未公开每击顿帧。

来源：[Dead Cells / Mechanics](https://deadcells.wiki.gg/wiki/Mechanics)（社区维护）；[Hi-Fi Rush / Xbox](https://www.xbox.com/en-US/games/store/hi-fi-rush/9nftc552k3gj)（官方商品说明）。访问：2026-11-14。

**我的推断：**保留 R1 的局部时钟；无敌、输入、镜头和粒子衰减继续走真实时间。优先调“快斩接触时停住，随后碎屑飞开”，普通攻击不再叠全局慢动作。三连第三段只增加低频冲击层、垂直碎屑和稍重停势，不让每击都像终结技。血条延迟段用暗色，明确只是损血历史；元素视觉只借形状分工，本项目不新增元素伤害系统。

### 3. 低成本武器特效：哈迪斯、Minecraft Dungeons、Teardown、Roblox

**媒体转述开发者作品：Hades**的 VFX/UI 艺术家 Josh Barnett 为不同神力制作雷电、波浪、箭等不同效果；文章未提供顿帧/镜头参数，也未据其嵌入视频作逐帧判断。**开发者自述：Minecraft Dungeons 的 Chris Nordgren**强调特效像素密度与环境一致、跨武器复用材质纹理，并为斧旋转/剑斩刺/锤砸地制作更夸张的动作表现；径向防护形状折中为六边形。他也反思过量径向渐变及一刀切的 unlit 烟雾优化。

来源：[Hades / 80 Level](https://80.lv/articles/a-behind-the-scenes-look-at-the-effects-in-hades)（媒体）；[Dungeons / 作者访谈](https://www.vfxapprentice.com/blog/mojang-vfx-of-minecraft-dungeons)（开发者自述，非引擎参数表）。访问：2026-11-14。

**官方技术资料：Teardown**把可生成实体与粒子 API 分开，粒子支持颜色、重力、阻力、碰撞和发光变化；体素场景不等于每颗视觉碎屑都要真实破坏。**Roblox 官方**明确 ParticleEmitter 是 2D 图像粒子，粒子尺寸影响填充率、重叠增加 GPU 开销。其每发射器限制是 Roblox 平台约束，不能当 UrhoX 预算。

来源：[Teardown / Particle API](https://teardowngame.com/modding/api.html#ParticleType)；[Roblox / 粒子发射器](https://create.roblox.com/docs/effects/particle-emitters)。访问：2026-11-14。

**我的推断：**体素感主要靠硬边剪影、阶梯衰减、少色和轨迹，不靠海量独立立方体。刀光缓存刃根/刃尖，按距离补段，不能照抄“过去 8 帧”而让 30/60FPS 尾长不同。白色内刃＋武器点缀色外沿，透明最多两层；残影优先只留剑，最多两份。重击蓄力用 4–6 粒向刃根收拢，满蓄一次亮刃；箭尾沿速度方向拉长，命中墙保留既有 0.8s 插箭，命中敌体则挂到该部位。拔/收刃只在挂点事件加 0.08s 小闪与金属声；进战手光熄灭，脱战就绪再亮，不做全屏转场。

### 4. 音画同步与敌人可读性：只狼、艾尔登法环

**社区资料：只狼**弹反能推进敌方架势、短暂打断，敌人也能弹开玩家攻击；其 Combat 页玩家留言用不同剑碰撞声判断敌人是否弹反，这是社区体验报告，非官方实验。**法环**轻重攻击、连段与防御反击有不同架势收益，架势击破后以发光弱点标示可处决机会。上述资料没有给出金属音波形、火花时长或音画容差，均**未确认**；不采信“弹反声调试了几百次”等未溯源说法。

来源：[只狼 / Deflection](https://sekiroshadowsdietwice.wiki.fextralife.com/Deflection)、[Combat](https://sekiroshadowsdietwice.wiki.fextralife.com/Combat)；[法环 / Attacking](https://eldenring.wiki.fextralife.com/Attacking)、[Stance](https://eldenring.wiki.fextralife.com/Stance)（均为社区）。访问：2026-11-14。

**我的推断：**借鉴其碰撞结果可辨认的思路：硬甲接触播短金属头音＋向侧面迸射火花，软体播低中频闷击，破甲额外碎裂尾音。命中声以实际结算为触发点，不能在 `hit_on` 无条件播放；破风按挥刃峰值播放。预警由抬头/压肩姿态、地面范围、吸气/蓄能声三路同步；只变红不足以判断招式。倒地触地帧才播落地声和地尘；死亡先失力再碎散。v1 无掉落系统，死亡确认音与 Boss 胜利短音就是奖励，不伪造金币掉落。

### 5. 镜头、UI 与手机/Web 预算

**我的推断，依据 Rise 的可调镜头、鸣潮的目标控制及 Roblox 的覆盖成本资料（URL/日期见上）：**横屏战斗焦点取玩家胸口与目标中心的加权点，玩家保持画面宽度 35–45% 区域，敌人与预警位于中央 70% 可视区；避开双侧触控区。镜头先碰撞回缩再做特效偏移，最终再检查遮挡；不要把震动直接叠入跟随位置造成漂移。v1 保留弱辅助、不加硬锁，准星四角收拢提示真实命中，不能把朝向修正冒充命中。

表现优先级：敌人前摇/危险地面 > 角色与武器 > 弱点/破甲 > 命中火花 > 环境尘。禁大面积白屏、普通攻击 FOV 泵动和全屏运动模糊；震动、FOV 冲击分别可关。尺寸与片段表均为推断，必须在 844×390 逻辑横屏和实际手机 Web 取景复查。

## 对本项目当前实现的差距清单

### P0：先补“打中了什么”

- `CombatMoves.Feedback` 已有分级顿帧和定向轻震，但反馈回调只传位置/重击标记/结果，缺武器档位、部位材质和冲击方向的完整语义。建议一次结算生成一次表现事件；声音、火花、HUD 共享它，避免重复触发。
- `EnemyParticles.Emit(owner,count,death)` 从敌人身体中段发射、方向按角度均匀展开，固定石灰色；未接收真实命中点/斩向，容易像“身体漏灰”。首先补接触点和材质分组，再加数量。
- `EnemyVisual.Update` 倒地仍把身体 Y 缩至 0.45；与主方案“不做缩放”的受击方向冲突，缺失承重与触地感。本模块也未见按命中部位消费白闪/关节回弹；跨模块最终效果未验证。
- 所读战斗表现模块未见音频播放链路。应先落实挥空/软击/硬甲/破甲/受击五类声，再评价是否还需更强镜头；全项目是否已有其他声音接入，未确认。

### P1：补节奏和闭环

- `CombatAnim` 已池化两份残影并按 0.04s 采样；这是姿态数据，最终刀光绘制与刃尖贴合尚未验证，不能算已验收。`fovAge` 已置零，实际相机消费也不在本次证据范围。
- `CombatHUD` 已有窄 Boss 条、失衡、破甲图标和默认关数字；损血条即时跳变，缺短延迟条/命中准星。满蓄事件已存在，应接一次性声光提示。
- 死亡立刻隐藏身体，交给通用粒子池，缺“失力→解体”起势；阶段环已有，但需组织咆哮/压肩/环扩散为一个序列。群攻跨帧会重置反馈时间，应按挥击编号合并。

### P2：测后再增强

- 弓插箭、战斗焦点构图、镜头遮挡和舒适性留待 Web 验收；不据静态代码断言画面失败。
- 64 个立方槽预建且不重建是正确基础，但每槽是独立体积，不能等同一次提交。`TimeSpells` 另有 900/500 粒池、80 碎块与 6 光束；只复用池化思路，不把法术爆发整套搬到每次命中。
