# R6：动作绑定与武器路径动画

调研日：2026-11-14（Asia/Shanghai）。只读代码、公开资料和三张指定 Web 截图，未运行游戏。【官方】指产品/工具官方文档，【作者】指模组维护者一手资料，【社区】指玩家资料，【建议】是本项目推导；建议数值均待 Web 验收，不是原作常量。

## 十条可执行结论

1. **终态推荐 B：先拆双臂的肘，再按滑步验收决定拆膝。**上下段仍是刚体体素块，无须蒙皮。A 可先验证路径，但一根定长手臂无法同时满足任意手位与贴脸拉弦。
2. 先统一武器坐标：现有弓弦位于模型 **−X**，射向应为模型 **+X**；剑弓分别设置握持校正，不能直接共用 Rx90。
3. 用“握点路径＋刀身方向/刀刃平面”编排挥击；刀尖由最终握点、旋转和实际刃长推导，不给刀尖和手两套互相矛盾的自由轨道。
4. 先做横斩、反斩、下劈三种明显轮廓，每招六个地标姿态；先关刀光确认弧线，再开特效。
5. 判定、取消和运动继续由现有片段事件驱动；新增路径不增加第二套战斗时钟，命中窗内刀必须经过目标区域。
6. 刀光连接连续采样的刃根与刃尖，按空间距离采样；低帧率大角度转动需要在片段时间轴补采样，不能只连两帧直线。
7. 背剑改为连续世界位姿飞行；飞到手前解父子关系，到手后再挂接。淡出换挂点再淡入不能表现飞行。
8. 浮现、飞行、收回、消散全部按秒推进；现有八帧渐隐在30/60FPS下时间相差一倍。
9. 左手推弓、右手拉弦，箭尾跟弦中点、箭头向目标，满蓄提示一次。瞄准降敏是本项目建议，未证实 Minecraft 原版自动降敏。
10. 滑步优先身体降重心和镜头小幅位置滞后；默认不震、不滚转、不加 FOV，保留 §18 的2.2m/0.32s与0.22s接攻击。

## 一、现状与差距

已读方案 §13/§18/§19、BlockCharacter、AnimClips、CombatAnim、WeaponRig、WeaponParts；NomiVoxelData仅看文件头骨骼表。角色有16根节点骨骼，臂挂body、腿挂root，没有肘膝。CreateVoxel接受层级，Update每帧重写基础姿态，CombatAnim后覆盖六个主骨；拆骨需要同步覆盖名单、基础姿态、挂点及旧片段。

剑招已有六姿态、躯干提前0.02s、武器附加欧拉轨道，但肩、身体、握持Rx90与附加旋转相乘后，刀尖轨迹不易直接编排。WeaponRig已有距离采样拖尾、两份残影和背后±2°滞后；背后转换却按八帧改透明度、中途Attach，没有连续飞行。

三张截图已查看：瞄准图中弓位于左侧且可见弦；重击与滑步图被前景栏杆遮住下半身，无法据此判定脚是否穿地。单张图也无法证明挥砍、镜头或速度曲线。后续应在无遮挡场地以正常跟随和固定侧视各录一次，不能把这些静帧当作动作已通过的证据。

## 二、成熟方块角色的绑定方法

**Minecraft / Player Animator / Better Combat。**【作者】Player Animator列出头、躯干、左右臂腿六部位，加全身body；支持偏移、旋转，加载bendy-lib后才有中段bend，并提供优先层和淡入淡出[1]。所以Minecraft风格不等于只能摆肩。当前README已声明停止常规维护并推荐PAL，本项目借鉴层次和数据即可。

【作者】Better Combat以Minecraft Dungeons战斗为目标，提供连段、前摇和武器姿态数据；制作指南采用Blender模板，建议前摇0–50%、打击转折50–60%、打击结束60–70%、收势70–100%[2]。这是制作建议，不能覆盖本项目已确认的短前摇；资料也未证明其运行时采用IK或Bezier。

对单段肢体的可迁移原则【建议】：挥剑靠躯干先转、肩臂后追、武器末端越过身体中线；拉弓靠身体侧转与双臂错位保持推拉轮廓；翻滚靠全身根旋转和双腿相向收拢，不能用胸部单独翻圈代替全身。带肘膝的绑定则能在不旋转整个肩部的情况下收手、收腿。各模组具体翻滚与拉弓片段本轮未逐帧核验，不声称Better Combat本身提供完整闪避系统；本项目也继续以滑步为正式回避。

**Epic Fight / Fresh Animations。**【作者】Epic Fight公开HumanoidArmature包含Arm、Elbow、Hand、Thigh、Knee、Leg[3]，确认其表现并非全部依赖原版单段肢体。其网格系统不能直接套到本项目刚体节点。Fresh Animations项目页本轮超时，基础包和玩家扩展也不可混称；是否给玩家新增肘部，本轮**未确认**，不作为证据。

**Roblox。**【官方】R6为六部位，R15为十五部位[4]；IK文档展示上臂—下臂—手的链，并用约束限制肘部弯曲[5]。增加肘的核心价值是：手固定握弓时肘仍能改变轮廓，另一手能贴脸。R6便宜且方块感明确，代价是手只能沿肩球面运动。

**Blockbench / Hytale / Teardown / Dungeons。**【官方】Blockbench的分组骨骼、pivot和关键帧适合刚体工作流[6]：先摆大姿态、检查轮廓和轨迹，再补缓动。编辑器支持IK不代表导出后运行时自动有IK。Hytale官方明确只用cube/quad、避免weight painting，按骨骼命名驱动动画[7]，说明无蒙皮也可有完整生产流程；其玩家肘膝结构本轮未逐项核验。Teardown官方动画入口提供角色、物体动画及IK相关指南[8]；人体具体分块未确认。Dungeons内部骨骼和路径算法未确认，能确认的是Better Combat作者借鉴其连段体验。

## 三、武器路径与轻量约束

【建议】在躯干参考空间定义轨迹：X右、Y上、Z前，单位米。圆弧用于横扫，三次Bezier用于蓄势、突刺和收回，几何与时间缓动分开。Bezier参数并非等速，可用16–32段弧长表映射距离，再施加速度包络。身体、头、腿保留姿态表演，手臂由目标修正。

下表为招式语义转成本项目的建议。怪猎、原神、艾尔登法环、Dungeons的精确骨骼曲线及其是否用路径算法均**未确认**，不能声称这些参数来自原作。

| 类型与参照语义 | 轨迹初值 | 可读性重点 |
|---|---|---|
| 横斩：怪猎/原神式身体带刀 | 方位右+70°→左−65°，胸到腰高度；刃尖离身体轴0.8–1.1m，钳到实测臂长+刃长 | 先反向引剑，过中线后继续收势 |
| 反斩：连段接上次收势 | 左低→右高，斜面20–35° | 起点承接上招，不先回待机 |
| 下劈：魂系重武器读法 | 头顶→正前下方，刃尖离地≥0.03m | 躯干后仰约10°再前压20°，身体和刀共同落下 |
| 突刺：剑尖先行 | 握点前送约0.08m，直进、微弧收回 | 不拉长手臂，距离主要由身体前冲提供 |
| 回旋：终结技 | 单向270–360°角路径 | 用连续标量角，不能让四元数最短路吞掉整圈 |

沿用轻击0.40s：0–0.10s蓄势，0.10–0.18s快速穿过打击区，之后过冲、回收。顿帧只由命中事件触发，空挥不顿；镜头恢复用真实时钟。刀光强调实际经过的弧线，不能画一个未走过的半圆代替挥刀。

### 一骨瞄准与两骨IK伪代码

以下是数学伪代码，不是UrhoX API。全部输入先进入共同父空间，结果再转局部；不能把世界方向直接写成局部欧拉角。

~~~text
# A：S肩，T手目标，r0静止肩到握点向量（含挂点偏移）
d = safeNormalize(T-S, previousDirection)
Q = twistAround(d, authoredTwist) * fromTo(normalize(r0), d)
hand = S + Q*r0                    # 肩球面，不能保证hand==T
error = length(hand-T)             # >0.03m提示重摆，不无限伸手

# B：a上臂长，b前臂长，pole指定肘弯方向
D = length(T-S)
dc = clamp(D, abs(a-b)+epsilon, a+b-epsilon)
x = safeNormalize(T-S, previousDirection)
y = safeNormalize(pole-S-x*dot(pole-S,x), previousBendAxis)
c = clamp((a*a+dc*dc-b*b)/(2*a*dc), -1, 1)
E = S + a*(c*x + sqrt(max(0,1-c*c))*y)
Tc = S + dc*x
upper = fromTo(upperRest, normalize(E-S))
foreWorld = fromTo(foreRest, normalize(Tc-E))
foreLocal = inverse(upper)*foreWorld
# 实际层级另计父旋转与静止基准；腕朝向独立对齐武器
~~~

一骨仍有绕臂轴twist自由度，但不能凭空折肘。两骨缓存pole，避免伸直时翻肘，并限制关节角。最终刀尖必须按解算后的手和刀重算；调试同时显示目标路径与实际路径，误差超限就重摆，不能只画理想弧线。

拖尾补采样也应使用同一条解算链：根据片段前后时刻重建躯干、肩、握点与刀方向，转角每约10–15°或刃尖移动每0.06–0.09m补一个样本，单帧设上限。若仅线性插值两个世界刀尖，快速下劈会切过圆弧内部，形成短直刀光。超时卡顿宁可断开拖尾，不能跨整段收势连接一条横穿身体的亮带。

## 四、对本项目的具体建议

### A/B取舍

| 方案 | 效果 | 成本估计与风险 |
|---|---|---|
| A 单段臂＋目标瞄准 | 单手大弧、节奏、背剑飞行、正确弓朝向 | 三招原型约1–2人日；贴脸拉弦、双手握剑、真低蹲仍受限 |
| B 刚体上下臂/大小腿 | 抬肘、贴脸拉弦、低姿滑步和辅助握持 | 双臂约3–5人日，双腿另2–3人日；包含分块、挂点、旧片段及Web验收，均为估计 |

**推荐终态B，沿用A的路径原型。**先修坐标和三招，再拆双臂；低滑步仍像直腿下沉才加膝。不能只加空elbow节点、几何仍全挂肩。应在生成源重分上下段体素、切开跨关节quad/tri并封口，不手改自动生成数据。脸、认可的头发层次、修长比例与服装细节保留。现有腿1.35非等比缩放在新增旋转子骨后可能剪切，应烘入几何/轴心或调整层级后验收。节点和几何提交增加的Web成本未测，不预先保证无开销。

拆分建议保留arm_right/left作为上臂名称，下挂forearm_right/left，手socket转挂前臂末端；腿同理保留leg作为大腿、另加shin。肘轴心必须从现有袖口和手的几何实测，不凭骨表取中点。先以所有新增关节零旋转，验收静止姿态与拆分前逐体素一致，再测试肘弯45°、90°、120°：肩不脱节、接缝不透底、手握点不跳、左右不反折。最后重摆拉弓与双手下劈，不能把旧整臂角度同时复制给上下两段。

### 路径动画数据格式

~~~lua
-- 草案，当前CombatAnim尚未支持；P0..P3为躯干参考空间米制坐标
path = {
  space="torso_reference", -- 出招时冻结参考朝向；位置随角色移动
  gripSegments={ -- 每段有自己的几何与时间映射，包含完整收势
    {phase="anticipation", kind="bezier", points={P0,P1,P2,P3}},
    {phase="active", kind="arc", center=C, radius=R, angles={70,-65}},
    {phase="recovery", kind="bezier", points={P4,P5,P6,P7}},
  },
  progressKeys=..., -- 各段局部时间0..1到几何进度0..1
  blade={axis="+Y", directionKeys=..., edgeNormalKeys=...},
  arm={solver="aim1", side="right", poleKeys=..., twistKeys=...},
  wristLimit=35, maxGripError=.03,
}
-- B时solver改twoBone；dur/phases/motion/events沿用现有字段
~~~

参考空间须明确：冻结出招朝向，躯干转身是否烘入路径只能选一种，避免身体转两次。刃长取blueprint，换锻造部件后重算刀尖。顺序：基础姿态→躯干覆盖→目标路径→手臂约束→握持校正→实际刀尖→拖尾。旧weapon.euler只留小幅腕部润色，不再叠另一条大幅挥刀。

三段路径的相邻端点须相等，切线方向尽量连续；连段切换从上一招实际握点混入，不能只按新招第一帧瞬移。第一轮只批准三招与单把默认剑的路径；通过后再用最短、最长剑刃检验相机外轮廓、地面安全与判定吻合，避免一次调完整武器目录而失去共同基准。

### 背后武器状态机与时间表

【社区】检索可见原神玩家讨论武器悬浮、使用后消失[11]；本轮未取得官方实现或逐帧角色对照。以下是满足用户语义的自主方案，不是原神内部状态机。

Hidden → Manifest → BackHover → ToHand → Held → ToBack → BackHover → Dissolve → Hidden。

装备逻辑、战斗态与视觉转换分开；单武器只保留一个可见实体，重入从当前世界姿态继续，不跳回起点。

| 过程 | 时间初值 | 表现与挂接 |
|---|---|---|
| 浮现 | 0.12s | 背后先3–5粒淡金体素，轮廓后实体，透明度0→1 |
| 悬挂 | 持续 | 剑保留body局部(0.12,0.05,−0.23)、斜35°；弓(0,0.15,−0.28)，朝向单独校准 |
| 飞到手 | 独立拔剑约0.12s；直接攻击≤0.08s | 解父到过渡根，Bezier绕同侧肩外；终点每帧取手，旋转Slerp；到手才重新挂接 |
| 持握 | 攻击/瞄准期间 | 握把贴手，禁悬浮滞后；不要求手伸到背后取剑 |
| 收回 | 0.18–0.24s | 先离手，再沿身体外侧回背；弓扫过空间大，取上限 |
| 停留/消散 | 停留约1.2s，再0.18s消散 | 战斗待机常显；停留倒计时仅脱战后启动 |

挂点是现有值，不保证不碰头发；要按轮廓验收。悬挂加垂直±0.008m、0.7–1Hz呼吸，角滞后1–2°、时间常数约0.10s；整体位移不滞后，免得滑步把剑甩远。剑用沿刃细粒子，弓沿两弓梢聚合；满蓄与拔收粒子分事件。

现有sword_draw的weapon_ready在0.126s，飞行须此前到手。直接攻击必须在首个hit_on前落手，不能另阻塞输入0.30s；是否改事件由接线者统一决定。受击中断冻结/重定向当前飞行，换武器撤旧过渡并隐藏旧实体，不能残留两把剑。全部进度按秒，不按帧。

### 弓姿态规范与“反弓”排查

【社区】Minecraft Wiki记录拉弓轻微变焦、满蓄弓抖动、松手射箭和移动减速[9]；未证明自动改变输入灵敏度。不同版本/资源包的手持与箭显示不能混用。

【建议】左手握把在左肩前约0.35–0.45m，弓竖直；右手拉向右脸/下颌外侧，肘向右后展开；身体侧转30–40°、头补偿看目标。须钳到实际臂长；A够不到就缩拉距，不能断手。B用两骨解算，不拉伸。

当前弓在XY平面，弦x=−6体素，距握把后0.18m；模型+X朝射向D、+Y朝弓上方、−X朝射手。拉弦中点再沿−X位移0→0.12m，两弦端固定在弓梢，形成V形；箭尾跟弦中点，箭杆过握把附近，箭头朝+X。现有launch={0,2,3}向+Z偏离弓平面，应独立核对几何与发射挂点，不能改伤害射向掩盖反弓。

排查：①显示模型三轴和弦中点；②停动画只校握把；③检查dot(Q*(+X),D)>0.98且dot(Q*(−X),D)<−0.98；④检查共用gripRest=Rx90；⑤左手位置镜像是否缺朝向校正；⑥查乘法顺序、Blockbench路径翻z而体素路径不翻z；⑦检查负缩放镜像；⑧正侧背三视角检查箭尾、弦和拉弦手。不能凭背面一图补yaw180°。

沿用瞄准0.18s混入、肩偏0.25–0.35m、可选FOV−3°；触屏降敏先试0.75倍并独立可调。满蓄亮边0.08s、短音一次，本体微动≤0.5°，准星不摇。释放右手先沿拉弦方向后撤约0.03m再放松，左手保持指向约0.08s，避免右臂大幅前甩、像推弓发射。
