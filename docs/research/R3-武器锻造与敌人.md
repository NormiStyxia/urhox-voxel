# R3：模块化武器锻造、体素战斗与敌人调研

调研日：2026-11-14。对照《战斗与武器锻造方案》§4、§5.5、§6。文中编号均链接至文末原始 URL，访问日期逐项列出。**“官方”是厂商或平台材料；“社区”是玩家整理，未由本次亲测；“推断”是本项目建议，不冒充行业标准。**

## 一、结论摘要：10 条可执行结论

1. 每槽只承担一两个清晰职责；颜色不改数值，长短与实际判定一致。
2. 用伤害、出手速度、破甲能力形成取舍；逐一排查无代价升级件。
3. 保持每槽 2～3 件，提供均衡、快攻、破甲预设，不搬完整武器树。
4. 比较固定为“当前装备→候选”；像素条之外显示实数和单位。
5. 横屏保留三栏，小屏把属性收进可展开区；56dp 点击区继续保留。
6. 预览固定握点与尺度，增加回正按钮；选色使用显式色板而非循环盲点。
7. 3cm 是建模网格，战斗辨识靠整体剪影；刀光用短阶梯带与少量方粒。
8. 首 Boss 保留三招，按招式逐步教学；破甲必须同时改变模型和战术。
9. 混编从“2 近战＋1 远程”开始；冲撞、击退、后撤全程检查岛缘。
10. 4000 体素不等于性能预算；记录面数、提交次数、透明覆盖和帧时间。

## 二、分专题详述

### 1. 部件数值、最优解与搜索成本

**官方：[S1] 王国之泪**将两种创造分开：究极手移动、旋转、连接场景物件；余料建造（Fuse）给武器、盾、箭附加物件、数值或能力，例如眼球箭追踪。不能把自由载具拼搭直接当成武器槽位系统。**推断：**本项目适合固定接口拼件；阔刃看起来厚重、细刃看起来轻快、晶簇明显带晶体，先让造型解释功能。

**社区：[S2] Warframe Zaw**由 Strike、Grip、Link 三件构成：刃头决定主要伤害分布及武器类别，握柄影响速度和伤害，配重以增益交换惩罚；最终属性以部件相加为基础，部分类型另有修正。锻造前能同时预览成品与属性，甚至预览未拥有部件；成品不能拆回原料。**推断：**借鉴职责与预览，保留本项目无成本换装，避免不可逆试错。

**社区：[S3] 怪猎世界**的升级树有分支，改变攻击、会心、斩味等；部分升级可回退。**官方平台刊载指南：[S4] 艾尔登法环**把强化、属性补正、战灰分开，且面板总攻击不等于实战伤害。**推断：**当前没有经济与成长，武器树只会增加层级；先做横向风格。按现表剑有 54 种、弓有 18 种组合，足够检查每个部件是否被另一件全面压过。

**建议数值模型（推断，依据 [S2][S4]）：**攻击＝基础值＋部件加成；速度＝1＋速度加成，动作时长除以速度；距离来自实际握点到刃尖，不再叠第二次长度倍率。例：攻击＋20%、速度－15%，连续攻击理论输出约为原来的 1.02 倍，但单次窗口表现不同；这只是校准示例，仍需比较破甲、重击和实际命中率。每件至少有一种适用场景，避免“晶簇同时伤害、范围、破甲全占优”。

**社区：[S5] 泰拉瑞亚**词缀同时影响伤害、速度、尺寸、击退，并存在明确的最佳词缀。**推断：**多属性本身不能消灭最优解。本项目不复制随机重铸；颜色纯装饰，组合以对虫群、打哨灵、破兽甲三种情境比较。

### 2. 锻造与装备 UI

**社区：[S2]**证实“先选槽位→看整体外观及属性→确认制作”可用；资料未确认其相机交互细节。**官方：[S6] Android**建议触控目标至少 48×48dp，更大更好。**推断：**56dp 合理，但必须按逻辑尺寸验收，不能把 56 物理像素视为 56dp。

**项目布局建议（推断，依据 [S2][S6]）：**宽屏用“槽位／大预览／属性”，窄横屏保留预览＋槽位，属性折叠为底部摘要。选中部件在整体预览中描边，提供可选分解图辅助找部件；不新增环形部件转盘。镜头以握点固定，统一覆盖最大武器，避免每次自动缩放掩盖长短变化；手动拖转后停止自转，设可见“回正”，双击仅作捷径。

属性显示“10→12（＋2）”“满蓄 0.70→0.82 秒”，降低耗时也算改善，不能只按正负号着色。剑显示攻击、攻速、长度、破甲／失衡；弓改为伤害、拉满时间、有效距离、移动瞄准。颜色区为“主／副／点缀”命名按钮＋六个带勾色块，选中时高亮模型对应区域；支持撤销、整套配色和独立改色。关闭取消、装备应用，比较基线始终是打开面板时的装备。

### 3. 方块武器的视觉约定

**官方：[S7] 我的世界地下城**同时提供近战、远程及装备附魔；已查看其官方 Ultimate Edition 主视觉：亮刃、深色握柄及外伸轮廓使武器从人群中分离。该图是宣传图，不能证明实机判定或粒子预算。**官方：[S8] Android/Arm**建议把几何投入剪影，避免手机看不见的小三角形，并允许适度夸张比例。**社区：[S9] Valheim**以距离、速度、击退与动作组合区分武器；它是低多边形参考，不是可编辑体素实现的证明。

**推断（依据 [S7][S8]）：**剑优先保证刃、护手、握柄三段可辨，弓保留弓臂与弦之间的负空间；世界视角看不见一格高光时，用亮暗大色带，而非增加粒度。背剑约 35° 可作起点，须检查与头发、披挂的重叠；弓横背容易扩大屏幕宽度，增加轻斜角并保持弦线完整。没有查到可照搬的标准挂角。

拔收武器用手接近握柄、短路径移动、到位再切挂点；不必模拟长剑完整穿过背鞘。刀光用两三层阶梯弧带、短寿命方粒，不能盖住敌人起手与核心。具体角度、粒数、时长均为本项目美术试验值，非上述产品官方配方。

### 4. Boss、混编、时长与岛缘

**社区：[S10] Valheim 首 Boss Eikthyr**有近战角击、远程电击、范围跺地三类攻击，说明三招可覆盖距离与走位选择；不代表所有首 Boss 都应有三招。**官方平台刊载：[S4]**强调动作承诺、观察敌人空当及失衡后的反击。**推断：**石甲兽三招合理，先单次冲撞教横移／引柱，再横扫教近身撤离，最后跺地教跳跃或闪避；二阶段先增加双冲，保留原有识别前摇。

**官方平台：[S11] 怪猎荒野**集中模式突出伤口，破坏伤口可造成硬直并给资源。**社区：[S12] 怪猎世界**另外存在部位破坏伤害，断尾、断角会改变模型。二者不是同一机制。**推断：**本项目应分清生命、局部甲值、全身失衡；破甲呈现裂纹→甲片脱落→核心显露，并兑现“腿破更易摔倒／背破能打核心”。破坏奖励不能只有掉屑。

**遭遇与时长（推断，依据 [S4][S10][S11]）：**先独立教虫和哨灵，再上 2 虫＋1 哨灵；同一时刻最多一只虫进入扑咬起手，远程发射错开，首 Boss 不带小怪。普通遭遇先以 15～30 秒、首次成功 Boss 60～120 秒为测试目标；**未确认存在通用手机标准**。HP600 若整场有效 DPS 为 6～10，约需 60～100 秒；有效 DPS 必须包含躲避、装甲和追击损耗，以 Web 录像和伤害记录校准。

**官方技术：[S13] Unity 导航**按角色半径向内缩可走面，使中心远离墙与悬崖。**推断：**解析移动同样应检查身体占地、前方落脚与整条冲刺路径；边距包含体半径及制动距离。击退、哨灵后撤也执行，不能只检查终点有地。路径不安全时转向内侧或取消冲撞；只在撞实物时给眩晕，避免虚空边界变成免费引柱。无需为此迁移引擎或引入完整 NavMesh。

### 5. Web／手机性能：有出处的数字与自定预算分开

| 证据 | 原文数字／条件 | 对本项目的意义 |
|---|---|---|
| 官方技术 [S8] Armies 手机技术演示 | 静态相机、Unity、64 位，约 21 万三角形／帧、约 30fps；士兵约 360 三角形 | 是特定演示，不是 UrhoX Web 安全上限；敌人数不直接迁移 |
| 公开技术文章 [S14] 0fps | 实心 8³ 方块：逐块 3072 四边面、去内面 384、贪心合并 6 | 体素数不能替代输出面数；这是理想几何例，不等于帧率倍数 |
| 官方技术 [S15][S16] Unity／MDN | 透明粒子叠加增加覆盖；WebGL 合批通常有益；没有统一敌人／粒子数量 | 优先共享材质、合并网格和限透明覆盖，不能引用成“支持几千粒” |

**本项目初始预算（推断）：**普通场景先限制 4 个活跃小怪或单 Boss、12 支箭、64 个短寿命命中／死亡方粒；远处休眠。模型沿用每武器≤4000、敌人≤3000体素，但另记面数、Draw Call、重建耗时；换色不重建，战斗不重建，预览停转时降频。以目标手机 Web 的 33.3ms／帧为保底目标，16.7ms 为提升目标。数量只是待测起点，不能承诺达标；这些产品公开的同屏粒子和敌人统一预算均未确认。

## 三、对本项目策划的建议

以下均为建议，**未修改原策划或实现**。

| 对照位置 | 保留／建议改成什么 | 理由与依据 |
|---|---|---|
| §4 槽位、默认解锁 | 保留；补三套推荐组合和单槽复原 | 低成本试验，降低找件负担 [S2][S3] |
| §4 stats | 区分失衡与部位破甲；补晶首蓄力修正、晶簇破甲与爆炸的明确定义；稳定握把补代价 | 当前统一示例字段不足以表达选项，晶簇／稳定握把存在全面占优风险 [S2][S12] |
| §4.3 判定 | 剑长只取实际几何；弓发射点改成握把附近箭台／弦扣的独立 socket | 避免长度重复增益，以及箭从弓臂上端射出的视觉错位；项目几何推断 [S1][S8] |
| §5.5 石甲兽 | 保留三招；背甲靠局部破坏暴露核心，半血只进入狂暴；如需保底开甲须明确是辅助机制 | 自动半血开甲会削弱定点破甲价值，混淆生命与甲值 [S11][S12] |
| §5.5 苔壳虫 | 统一“背壳／正面减伤”方向；肚皮仅在扑空翻身时可打，或改成侧腹弱点 | 四足贴地时肚皮可能不可瞄；弱点必须可达，属本项目推断 [S11] |
| §5.5 布置与边缘 | 先 2 虫＋1 哨灵，Boss 独立；补按体半径收边与全路径检查 | 降低触屏注意力冲突，防止大体型中心有地但身体悬空 [S13] |
| §6 面板与预览 | 保留三栏和 2D 降级；小屏折叠属性、显式回正／色板、实数对比 | 56dp 与所有信息同时铺开可能挤压预览 [S2][S6] |
| §6 不暂停世界 | 仅安全区开放，或进入警戒立即关闭并保留草稿；“一帧完成”改为实测目标 | 脱战不等于不会新受袭；跨设备一帧耗时不能预先保证 [S15] |
