## 最小运行差异：只增加限量 Probe，不改变运动

仅改 scripts/ruins/SkyAtmosphere.lua：复用现有 DebugLog skyfx probe。
默认 debugLog=false；关闭时没有新增 Update 分支、计时器、Getter、字符串或日志。
开启现有调试日志后，每 5 秒的 probe 最多附加六次云运动快照，预算归宿主实例所有，
切档不重置预算。每次读取持有材质与 CustomGeometry:GetMaterial() 的 cloud_wind、
drift_time、cloud_enabled，**都是 CPU 材质参数读取，不是 GPU readback**。
六次之后不再查询材质；重新进入场景可重新取六次。标准既有 skyfx 摘要不受影响。

字段：hostClock/cloudStep/hostStopped、settingQuality/settingMotion、motionEnabled、
cloudElapsed/cloudLoading、luaWind、ownedMaterial、drawMaterial；已有字段保留
active/quality/cloudReady/cloudUnavailable。未设置的持久化值显示 nil，不能把 nil
误读为 false；resolved motionEnabled 才是本实例开关。
材质缺失和 getter 异常分别显示 missing/readback-error，绑定查询异常显示
binding-readback-error，不抛出异常到玩法更新。

不改 shader/图集/速度/世界朝向/异步回调/草地/AO/夜间/Scene。纹理采样仍一次，
三角形、draw call、常态 CPU 更新频率和 GPU 成本均不增加。最多六次 probe、
总计 36 次 Material 参数查询；没有新增运行资源，也无新增 meta。

## 后续同版 Web 分支检查

这份诊断还**没有构建**，当前远端不会出现新增字段。只有后续得到构建授权，
再将 SkyAtmosphere.lua 随正常 Maker 构建发布；不要为此手动同步/提交或自动构建。
在实际发生静止的设备/会话中开启现有调试日志，保持镜头 30 秒取六组：

1. settingMotion=false 且 motionEnabled=false：按用户明确设置冻结，先确认 UI 预期；不要无条件覆盖设置。
2. hostClock 不变或 hostStopped=true/active=false：沿宿主调用链定位，而非加速度。
3. hostClock 增长但 cloudElapsed 不增：区分开关、云实例重建、loading/unavailable 和丢失 dt。
4. luaWind 增而 ownedMaterial 不变：检查 Variant/参数写入；ownedMaterial 与 drawMaterial 不同则检查绑定。
5. 三者均增但真实轮廓不动：再检查实际设备后端 uniform 上传与顶点变体；CPU Getter 不能排除 GPU 问题。
6. 位移存在但很小：用该设备视角/分辨率/FOV 量化，不把主观“不动”直接归为逻辑冻结。
