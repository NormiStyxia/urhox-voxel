# 武器选择：右手平举与环弧面板

2026-11-15 用户确认方向并授权协同实现。调研和开发协同使用 maker GPT 供应商的 GPT 6.1sol。

## 表现目标

人物右手平举，掌心附近展开一段中空圆环。面板有清楚的内外弧，端部圆润；不能做成朝中心汇聚的尖角扇形。剑和弓沿弧分区，类型由数据驱动，后续扩展不依赖“两种武器各占半圆”。

构图以人物、掌心和弧段为主。细刻度、编号、定位点与引线建立结构图感；深墨蓝透明底、米白主线和少量琥珀选中反馈。装饰不压过武器图标与名称，不改人物体型、脸、衣服或已有武器造型。

原神轮盘作为交互参考。用户提到的《明日方舟：众生行迹》背景结构图需要核对具体来源；来源与观察结论单列于调研记录，不把自行编排称为原作复刻。

## 操作与状态

- 桌面保留战斗态 Q 入口：按住呼出，移向选项，松开确认。Esc / 右键取消。Tab 保持远眺。
- 手机保留切换入口：点开后，再点剑或弓确认；点空白取消。打开按钮的那次手指释放不能误选。
- 仅确认时切武器；取消和选择当前武器不播放切换动作。攻击、蓄力、移动和镜头输入不能穿透面板。
- 开启期间隐藏准星、操作按钮、时钟、提示横幅和帮助，保留生命与任务信息。世界继续运行；失焦、受击、死亡、骑龙、其他菜单、虚空回溯和退出场景应终止选择。
- 收起后等待相关按键与手指释放，再恢复玩法输入，避免误放箭或误挥剑。
- 人物最终姿势与当前相机更新后采样右手投影；界面遵守安全区，窄屏时压缩构图但保留可点选尺寸。

## 接入分工

- 环弧面板：独立 UI 模块，复用现有 UI 浮层及 NanoVG 帧，不替换 HUD 根节点。
- 人物抬手：独立姿势模块，使用现有肩肘与共享掌心挂点，在基础/战斗动画之后叠加。
- 场景：负责打开条件、Q 松开确认、战斗切换、输入隔离和退出清理。
- HUD：只调整选择期间的显示优先级和操作说明。

## 验收边界

本轮不自动提交、远端构建或启动本地 Runtime。离线测试覆盖状态和几何契约，不能代替 Web 实机视觉验收。

开工基线 `tests/combat` 36 套中 34 套通过；`core_motion.lua:71` 和 `forge_showroom.lua:254` 已失败，保留为基线，不在本轮扩大修改。

Web 验收重点：右手是否自然平举、掌心引线是否贴合、弧面是否避开人物、剑弓是否易认；30/60 FPS 动效；横竖屏与安全区；重复开关、取消、失焦、受击后的姿势与输入恢复。

## 已实现与整合结果

- 60°左右的两个选择区共用一段122°环弧；内半径88dp、外半径164dp，按安全区自适应。6dp外推展开约0.12秒，关闭淡出0.10秒。当前剑/弓均分，UI可通过 items 数组扩展；新类型的战斗逻辑仍须相应接入。
- 右手约0.18秒抬起、正常关闭约0.12秒放下；基于真实肩肘及掌心向量，支持现有两套骨架，不改骨骼支点。受击等硬中断立即交还动作控制。
- 首次打开遵守既有攻击取消窗口；取消拉弓会清除待发箭。选择当前武器是无动作操作，选择另一类型保留现有切换动画及锁定时序。
- 修复了接线中发现的触控取消递归：轮盘自己清空触摸不再误关自身，关闭时清空输入也不再抹掉已确认的切换动画。
- 新增两个模块及两个测试的 .meta 均由 Maker 官方 generate_resource_meta 生成。

离线验证：新增两套测试均通过，包括实际场景 takeInput / releaseInput / onCancel 回调、Q松开、指针恢复、受击、蓄力取消、骨架挂点、同类型确认、DPR和多指隔离。检查的6个运行脚本及2个新测试均为0个LSP Error。全战斗测试本次执行38套、37套通过，唯一失败为原有 core_motion.lua:71；并行任务期间原 forge_showroom 失败已不再出现，不能归为本功能修复。
