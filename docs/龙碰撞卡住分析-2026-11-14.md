# 龙与场景体素碰撞：卡住原因与处理建议

日期：2026-11-14。范围：当前遗迹场景的大号龙、骑乘/飞行控制及场景体素查询。
本次为源码研究，未改运行代码，未启动本地 Runtime、远端构建或 Web 预览。下面区分已确认的代码问题与仍需 Web 复现的触发情况。

## 结论

现有实现存在“能挡住部分运动，但不能保证最终姿态不穿插，也不能从重叠中恢复”的缺口。优先修龙的运动解算，不宜直接缩小全部碰撞尺寸或删除场景碰撞。

龙的体素骨骼是视觉部件（DragonRig 不 Finalize），遗迹场景将其设为 layer=2、mask=0。实际阻挡来自 RuinsDragon.ResolveMotion 的 7 个骨骼球体扫掠，并不是整条龙参与刚体求解。诺米另用 VoxelCharacterController。

## 已确认的问题

1. **任何部位碰撞都会同时截断位移、转向和升降。**
   `scripts/ruins/RuinsDragon.lua:55` 使用统一 fraction，碰撞后清零 speed、yawRate、vel；有竖直运动时还清零 vy。没有把剩余位移投影到墙面滑动的步骤。头、尾根或胸部碰到一个角落，都可能妨碍整条龙转身脱离。

2. **检查的运动与最终显示的位置不一致。**
   `scripts/dragon/DragonAnimationController.lua:964` 先调用 resolveMotion，随后 ApplyPose 才更新地面/airFloor 高度、俯仰、侧倾、骨骼 FK 和 IK。扫掠只含 L.pos、L.alt 和 yaw 的变化，没有涵盖地面高度变化与本帧动画引起的球心位移。`ApplyPose` 还可能直接抬高 L.alt。此顺序允许“检查通过后又进入障碍”的情况；具体在哪些物件上发生需 Web 验证。

3. **没有重叠恢复。**
   ResolveMotion 在无位移、无转向时直接返回，且没有独立的穿透检查、推出或安全位置恢复。动画、移动机关或恢复体素造成的重叠没有专门的收敛路径。SphereCast 对初始重叠的距离/法线行为，本地文档没有明确说明，不能把扫掠当作可靠的穿透恢复接口。

4. **偏航跨 ±180° 时的碰撞插值有确定的角度错误。**
   Flight.Move 会 Wrap 偏航；ResolveMotion 回退却直接计算 `oldYaw + (newYaw-oldYaw)*fraction`。例如 179° → -179°，fraction=0.5 时得到 0°，正确短弧中点应为 ±180°。这会在恰好跨界且被阻挡时把龙转向未经扫掠的位置。必须统一使用最短有符号角差，并分段检查旋转圆弧。

5. **地形与落地只检查了有限条件。**
   queryGround 从参考高度上方 6m 向下取首个朝上的命中，未限定“当前脚底附近的可承重表面”；低拱顶/横梁可能成为候选。canLand 检查永久岛面范围和中心射线，不检查躯干落地后的净空。地面移动的高差阈值也不等于真正的抬升、前移、向下找支撑的跨阶过程。

6. **地面没有倒退输入。**
   `scripts/dragon/DragonRide.lua:291` 中 S 和触屏向后都表示停止，不能直接倒出死角。增加缓慢倒退会改变现有操作语义，应作为手感改进独立处理；不能用它替代碰撞修复。

## 建议实现路线

### 第一阶段：稳定核心碰撞与移动

- 让躯干使用固定在运动根节点上的少量重叠球体，形成连续的近似胶囊包络；不要让呼吸、低头、甩尾每帧改变主要阻挡形状。尺寸从当前各型号实际体型测量，不能仅凭骨骼 pivot 或统一缩放猜测。保留头部前方障碍探测；翅尖、尾尖主要约束姿态，不负责锁死整条龙。
- 所有最终根节点位移（含地形高度、升降）先形成候选，再进行连续扫掠；碰撞解算后动画不得二次修改物理位置。运动位置与视觉姿态各有唯一写入位置。
- 先走到碰撞前的安全间隙，再去掉剩余位移中朝墙内的法线分量，保留沿墙运动；采用有限次数的重复扫掠，处理墙角。位移、转向、升降分别检查，但每个接受结果都必须基于已更新的位置重新查询，不能简单放行转身或上升。
- yaw 使用最短角差；旋转按角度/端点弧长分段，避免仅以起终点弦线代表长身体的扫转。
- 明确场景查询 mask，排除视觉部件；核对静态建筑、动态碎块、冻结/回溯物件各状态的过滤规则。当前没有证据证明龙自碰是主因，不能只改 mask 就宣布修复。

### 第二阶段：重叠恢复与地面支持

- 即使无输入，也需要处理机关/体素恢复造成的重叠。优先查证当前运行时是否提供可用的重叠与穿透深度查询。现有 Lua 声明明确暴露 SphereCast，但不能假设存在通用 OverlapSphere/ComputePenetration。
- 若继续采用自定义多球解算，必须设计并验证对应的重叠查询/推出方案；不要用一条射线或球心是否在体素内来声称整球无碰撞。浅重叠按受限距离恢复；失败时仅回到最近的、重新确认有支撑且净空足够的安全位置。世界发生变化后，旧安全点也可能失效。
- 地面用前后/左右多个支撑采样，并按脚底高度限制候选地面；跨阶依次检查向上净空、前方通路、落脚支撑，避免单纯读新高度后抬高模型。降落前检查躯干占用和周围净空。
- 若要借用 VoxelCharacterController，其文档已提供 penetrationRecoverySpeed、enhancedInternalEdgeRemoval、stepHeight 等能力，可用于核心胶囊方案的验证。但默认竖直胶囊不能直接完整代表长身体的龙，仍需处理头尾、旋转和飞行高度所有权；不建议未经原型验证直接整体替换。
- 不添加 Bullet 的 RigidBody/CollisionShape：它与当前 VoxelPhysicsWorld 是不同系统，不会自动与现有体素碰撞。

## 建议先后顺序

1. 加可开关的碰撞球/命中点/法线显示，记录阻挡骨骼、目标 volume、运动前后位置、yaw、alt 和最终 root 高度。
2. 修复角度跨界、根节点高度二次修改、碰撞统一急停；先保持模型与场景资产不变，便于对照。
3. 稳定躯干代理，补重叠恢复、多点支撑与落地净空。
4. 单独评估缓慢倒退、收翼、收颈避障等手感和表现。

## 验收清单（Web 预览）

| 场景 | 必须观察到的结果 |
|---|---|
| 斜着顶墙并持续前进 | 贴墙移动，不因轻微接触整体锁死 |
| 柱子旁/内外墙角转弯 | 可沿有效方向脱离，不允许转身穿墙 |
| 179° 附近受阻转向 | 不突然转到 0°，只走短弧 |
| 石阶、坡面、台阶边缘 | 可走台阶稳定通过，高墙阻挡，无突然抬升穿顶 |
| 低拱门、横梁下方 | 不把顶面当脚下地面，不向上吸附 |
| 飞行斜撞墙、上升碰顶 | 阻挡法线方向，仍保留合法切向运动 |
| 柱旁降落、狭小落点 | 净空不足则拒绝降落，状态不提前判为落稳 |
| 静止时摆头/甩尾及机关恢复 | 核心不嵌入，软部位有明确避障/容许穿插标准 |
| 初始浅重叠、碎块挤压 | 有限时间内恢复；失败采用经复查的安全位置 |
| 30/60 FPS 与单帧卡顿 | 不因速度/转角增大穿过薄墙；查询次数有预算 |

现有 `tests/ruins/interaction.lua` 仅以查询替身验证直线撞墙截停与无障碍放行，无法证明真实体素接触、滑墙、动画穿插或初始重叠正常。本次没有运行该测试，也没有声称问题已修复。
