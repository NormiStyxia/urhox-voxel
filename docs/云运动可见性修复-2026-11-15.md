# 云运动可见性修复（独立A报告，未构建）

基线 beab427d408a3bad919aa5a9063bd851c0212bc0。本报告只涉及云；夜间/AO由B另行处理，不改其文档、DayNight、SceneQuality、GameSettings、夜间模块、Scene或玩法。运行最小差异与原始快照见 validation/sky-fx/motion-visible/。

## 已证实与尚待证实

- 用实际旧 SkyClouds.lua 在 Lua5.4 重现：预算4的 horizonOnly=true，moving恒false且t强制0；即使cloudMotion开启，20秒后位移仍为0。真实GameSettings自动降档可进入该档，这条代码路径确实会冻结云。但没有拿到用户这次实际持久化设置/已发布Web运行值，不能断言它是用户反馈的唯一原因。
- 中高档原基础风X=0.24m/s、Z=0.10m/s，在约500m半径天球上短时间角位移较小，是可感知性候选因素，不等于所有视角都静止。
- 实际调用链：RuinsScene.Ruins_HandleUpdate取eventData.TimeStep，经Safe('Sky.Atmosphere',...)交给宿主；宿主0.2秒门槛后调用SkyClouds.Update，再写cloud_wind/drift_time；世界空间vertex实际消费这两个uniform。Scene在这两行之前没有暂停菜单早退，DayNight快进不是云时钟来源。没有改调用入口。
- 旧Update对每次dt夹到1秒，低帧率/恢复时会丢时间；颜色时钟初值0.2也会被误算入运动。旧代码冷下载等待期间不累计运动时间。以上是源码/离线可证实问题，并非GPU观察。
- 官方state.json只证明日志轮询回执；runtime.log本地不存在（runtime-evidence.log保留原错误）。没有操作浏览器、不能确认线上hash/当前档位/cloudMotion值/uniform上传是否生效。请求B或Lead在统一浏览器观察时记录这些值及固定镜头20秒前后画面，不能把变量数值变化当视觉验收。

## 最小修复

1. 所有档位都推进整体风；低档motionDetail=0只关呼吸/起伏，云影仍关闭。motion=false明确冻结位移，速度分量0。无资源/零预算/Dispose路径不新增渲染或重试。
2. 基础X风1.20m/s、Z风0.36m/s，缓变幅度0.12/0.06m/s；保留解析积分、层倍率0.5/1/1.5、独立环绕/淡出和3600m共周期。纹理、云形、天空配色、世界朝向均不变。
3. cloudStep仅累计真实传入dt；不再拿“强制刷新颜色”的0.2秒充当运动时间。累计下载中的逻辑时间，完成后第一次显示即消费当前相位；超过1秒的真实有限dt不截短。停止调用Update相当于暂停；如果引擎恢复时传入大dt，就跟随该dt推进，不读取墙钟制造额外追赶。
4. 仍在宿主约5Hz一次上传运动/着色/云影，云影沿用同一wind对象。没有每帧上传、数组、顶点重建或纹理读写；每帧只新增一个标量时间累计。增加速度没有新增GPU指令或采样：RuinsCloud.shader仅一条说明注释变化，剥注释后顶点/片元与基线完全相同，片元仍1次texture。原Variant上传开销保留，没有新增每帧Lua对象构造。
